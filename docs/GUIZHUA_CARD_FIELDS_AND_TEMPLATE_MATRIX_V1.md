# 归爪｜卡片显示开关字段清单 + 模板适配表

版本：V1.0 · 2026-09-29  
用途：作为最新一轮 Codex 开发任务的补充规格，固定内容开关、模板能力、默认状态、信息来源与验收要求。  
范围：统一日常记录的卡片投影、模板与印记交互；不借本文件重做首页、登录、云同步或问诊服务。

> **记录是一份，展示可以不同。关掉卡片中的健康信息，不删除健康记录，也不改变现有授权范围内的问诊取材。做出卡片、盖章、换模板都不是健康记录保存成功的前提。**

## 0. 依据、变更与实现边界

用户最新明确方向优先：健康记录、生活片段、观察、状态与照片属于同一个“日常记录”体验，而不是相互竞争的两个系统。内部不同数据仍要保留语义与来源。

已有交付文档提供的基线：

- `HOME_IDENTITY_REWORK_20260928.md`：旧一轮仍按健康与生活分别保存；已记录朱印/压印、本地印记快照、改名、主视觉偏好及 V3 照片页/信纸。这不是新融合规格已经实现的证明。
- `DUAL_MODE_IMPLEMENTATION.md`：已有模板 ID 为 `quote / letter / day / collage / date / habit`；已有记录、照片、草稿、作品快照与版本保护。
- 健康交付所说的“5 状态 / 12 事件 / 手写记录”，不能直接视为已经存在十二组带数值、单位和结果的结构化健康字段。

本文件下面的字段均为**逻辑字段/新交互规格**。Codex 先与当前实际结构建立映射，缺字段就明确缺失，不能假造数据，也不要为了命名一致迁移或覆盖所有旧资料。默认值、模板限制、视觉参数是本轮建议规格，不是假称用户逐项确认或已经通过实测。

“统一日常记录”不等于必须把既有数据库强行合成一张表。可以先用兼容适配层聚合同一账号、宠物、日期的资料。保留原 ID、版本、时间和字段，不按同一天粗暴覆盖多次观察。旧健康链路必须继续有效。

## 1. 必须分开的三件事

| 层次 | 内容 | 控制方式 |
|---|---|---|
| 原始日常记录 | 结构化健康、用户观察、生活文字、状态、照片与事件时间 | 在日常记录编辑器修改；来源字段和用户原文保留 |
| 问诊资料 | 已授权范围内与咨询有关的原始健康及观察，保留日期、来源和未知项 | 沿用问诊取材规则；与卡片开关无关；不直接读取排版结果或润色候选 |
| 卡片作品 | 用户选择展示的资料、文字版本、素材、版式和印记 | 本文件定义的内容开关与模板配置 |

例：用户记录“食欲比平时少；傍晚在窗边待了一会儿”。卡片可以只显示窗边片段；食欲观察仍保存在原记录中，并能在既有授权和相关性规则下进入问诊。不能因为分享图片不显示食欲，就从问诊里删除它；也不能因为写了生活片段，就补全所有健康项为正常。

卡片开关不是“允许 AI 读取”开关，也不是“删除记录”操作。若以后新增问诊资料授权，使用独立设置，不借用卡片展示开关。

## 2. 用户实际看到的开关面板

入口固定为：成品预览 → `这张卡显示什么`。

采用“上方实际预览、下方分组底部面板”，不把二十多个开关全部摊在记录编辑首屏。一级分组：

1. **卡片内容**：文字、照片、健康与状态。
2. **名字与日期**：身份、日期、称呼、署名。
3. **纸面与印记**：横线、插画、纸纹、相框、朱印/压印。

健康项目在“健康与状态”里继续展开，默认显示已记录内容，不要求用户先理解英文字段。没有来源的选项不占主面板；在“查看其他内容”中可说明“这一天还没有记录”。

已选择但当前模板无法放入的模块不可悄悄消失：面板顶部显示 `有 2 项内容不适合这个版式`，可选择换模板、在支持分页的模板中分成多页，或明确从本作品移除。

底部只保留 `完成`，修改应更新同一个真实渲染预览。不把“完成设置”误写成“已存入相册”。

固定短说明：

> 这里只决定卡片上显示什么，不会改动原记录或问诊资料。

## 3. 内容显示字段清单

默认说明：

- “有内容时开”只适用于有明确、安全来源且当前模板支持的字段；没有内容就不制造占位。
- 健康、手写观察、额外备注、主人心情默认关。用户在本作品中主动选后才进入成品；不要自动继承上一份作品对健康资料的分享选择。
- 默认是新作品的初始值，不覆盖用户已经修改过的开关。
- 下列字段不是强迫新增所有录入框；没有真实来源的字段可以保持不可用。

### 3.1 内容与来源

| 逻辑字段 | 用户看到的名称 | 新作品默认 | 数据来源与硬规则 |
|---|---|---|---|
| `text.life` | 生活片段 | 有内容时开 | 用户明确写入的生活正文；可选择原文或已经主动采用且版本有效的候选，不自动调用 AI |
| `text.observation` | 手写观察 | 关 | 原始健康观察/手写记录；默认展示原文，不以 AI 改写替代事实，不改药名、数量、单位、否定与时间 |
| `text.notes` | 其他备注 | 关 | 独立的真实备注；旧版只有一个手写字段时，不能再复制成另一段备注 |
| `text.letter` | 写给它的话 | 信纸有正文时开 | 用户写的信或明确选为信件正文的回忆；称呼、落款单独管理，不自动捏造回信 |
| `text.quote` | 这一句话 | 短句模板必选 | 用户指定的一句话/节选，或手动输入；来源保留，不能自动摘掉否定、改变意思或用省略号隐藏溢出 |
| `text.habit` | 它的小习惯 | 习惯模板必选 | 用户确认的习惯/偏好内容或明确选入的来源片段；不是 AI 猜测的性格结论 |
| `health.overall` | 主人记录的整体状态 | 关 | 只用用户明确选择的整体状态；不从照片、生活文字、记录频率推断健康结论 |
| `state.petObserved` | 宠物当时的表现 | 关 | 明确是主人观察宠物的状态；不是 AI 判断宠物心情 |
| `state.ownerMood` | 我当时的心情 | 关 | 仅在用户明确记录了自己的心情时有值，绝不当成宠物精神状态 |
| `health.items` | 健康项目摘要 | 关 | 开启后逐项选择已有的真实结果/数值，不等于全部健康信息自动公开 |
| `health.eventTags` | 记录过的事件 | 关 | 对“洗澡/清洁”等只有事件标签的旧资料作准确展示；标签不是完成凭据或正常结论 |
| `media.photos` | 照片 | 已明确选为卡片素材时开 | 选择具体照片 ID 与顺序；用途不明、病灶/报告类资料先让用户选择，不能默认把所有附件放上卡片 |
| `media.photoCaptions` | 照片说明 | 关 | 用户已写的照片说明；不自动识别场景、地点或编一段故事 |
| `media.petPortrait` | 使用已有宠物形象 | 关 | 用户主动选择已有形象/肖像素材；与主照片按模板互斥或二选一，不重新生成图片、不随首页展示偏好擅自替换卡片素材 |

### 3.2 身份与时间

| 逻辑字段 | 用户看到的名称 | 新作品默认 | 数据来源与硬规则 |
|---|---|---|---|
| `identity.petName` | 宠物名字 | 有名字时开 | 新作使用当前名字；旧作品使用原快照；关闭后联动移除系统自动排入的名字和印记文字，不改用户原文 |
| `identity.title` | 标题 | 有用户标题时开 | 只用用户填写/确认的标题；模板名称不自动冒充作品标题 |
| `date.display` | 页首/页脚日期 | 陪伴常规模板有日期时开；怀念默认关 | 可选事件日期或书写日期，显示明确标签；模糊日期按原精度展示，不用创建时间假装事件发生时间 |
| `identity.salutation` | 称呼 | 信纸有称呼时开 | 使用用户填写/确认的称呼；不擅自补“亲爱的”、改宠物称谓或重复正文里已有称呼 |
| `identity.signature` | 署名 | 关 | 用户自填；不自动填登录账号名、手机号、真实姓名或煽情落款 |
| `identity.topicTags` | 小标签 | 关 | 用户选定的生活主题；不添加算法推断的病症、性格与“健康优秀”等标签 |

### 3.3 不合并、也不重复的规则

- 旧“轻松/平稳/疲惫/不安/不适”字段必须先核对语义。不能默认认定是主人心情，也不能复制到“整体健康”与“宠物心情”两处。
- 旧字段主体不明时，保守显示 `当日所选状态：平稳`，必要时请用户确认；不要静默改变旧记录含义。
- 若两个可见模块映射到同一来源 ID、字段路径、版本及文字范围，合并为一次呈现，并在面板提示“已包含在手写观察中”。
- 不按“文本一样”删除来自不同时间的独立观察；同样的体重数值在两天出现不是重复数据。
- 同一主体、同一来源的整体状态与表现标签不能双份重复输出。已有真正独立来源时可以并存。
- 只有一段旧手写文字时，先保留为一段原始记录。不让模型自动拆成健康事实、生活经历与额外备注三份。
- 用户通过“编辑记录”改变原始文字是记录操作；通过“调整卡片文案”编辑展示文字是作品操作，不能悄悄互相覆盖。

## 4. 健康子项开关：十二类逐项处理

`health.items` 是总入口，子项选择是具体清单。关闭总入口暂时隐藏，保留本作品内的子项选择；重新开启后恢复原选择，不能扩大成全选。

**首次开启不立刻公开所有项目。先列出真实有内容的项目，让用户确认选择。** 可以提供“选择基础观察”快捷项，但只选择有真实结果的饮食、饮水、精神、排便、睡眠，不依据“结果正常/异常”挑选或隐瞒。

| 子项逻辑键 | 用户名称 | 可显示内容，仅限实际有数据 | 首次快捷选择规则 |
|---|---|---|---|
| `food` | 饮食 | 用户记录的食欲描述、数量与单位、时间 | 基础观察可选；无真实结果不填“正常” |
| `water` | 饮水 | 饮水观察或明确测量值、单位 | 基础观察可选；不能从有水碗照片推断饮水量 |
| `energy` | 精神 | 主人记录的精神/活动反应 | 基础观察可选；不重复同来源整体状态 |
| `stool` | 排便 | 已记录频次、性状与时间 | 基础观察可选；绝不默认展示病灶照片 |
| `weight` | 体重 | 测量值、单位、测量日期 | 单独选择；不从单次值生成趋势或体型判断 |
| `sleep` | 睡眠 | 用户观察/明确记录的时长 | 基础观察可选；无数据不估算时长 |
| `activity` | 外出/运动 | 用户明确记录的活动、时长 | 单独选择；不自动附带定位、路线或住所 |
| `grooming` | 洗澡/清洁 | 用户明确记录的事件及日期 | 单独选择；仅类别标签就按类别展示，不补“已完成” |
| `preventiveCare` | 疫苗/驱虫 | 用户填入的事件、日期和已存在说明 | 敏感扩展，默认不选；不自动新增用药建议或下次日期 |
| `medication` | 用药 | 原始药名、数量/剂量、单位、频率等已填信息 | 敏感扩展，默认不选；按原记录输出，不自动整理成处方 |
| `symptoms` | 异常情况 | 用户原始异常观察、时间 | 敏感扩展，默认不选；被选中后不能为了美观删掉异常或否定 |
| `misc` | 小事/备注 | 既有独立备注原文 | 默认不选；与 `text.notes` 同来源时只显示一次 |

### 4.1 旧数据只有标签时

“选了饮食”不等于“食欲正常”；“选了疫苗/驱虫”也不证明已经接种或服药。

- 没有结果值的项目，在健康结果列表说明 `尚无具体观察`，不填假值。
- 用户主动选择展示类别时，走 `health.eventTags`，措辞为 `记录类别：饮食、饮水` 等准确描述，不冒充健康摘要。
- 备注里有观察但没有结构化字段时，可展示原始备注；不得为了补齐矩阵自动抽取并写回医疗事实。
- 当前记录与旧记录同日不自动相互覆盖，摘要保留记录时点；选择“最新一次”必须显式说明依据，不能当作全天状态。

### 4.2 健康内容的必要说明

出现 `health.overall / health.items / health.eventTags / text.observation` 的健康来源模块时，保留一行精简的必要说明，例如：

> 主人记录节选 · 2026.09.29 · 非诊断

用户开启任意健康模块时，面板同时说明：`卡片只展示你选的项目，不代表完整健康情况。`

这不是“页脚装饰”，不能随品牌页脚开关被隐藏。`date.display` 只控制装饰性的页首/页脚日期；健康资料自己的事件日期仍属于健康模块。未知或模糊日期按实际精度显示，不强制伪造具体日期。

必要说明不应挤满卡面，但要可读。不能把普通观察包装为“体检报告”“健康证明”，不生成健康分、健康优秀、全部正常或疾病诊断。

## 5. 纸面、印记与交互字段

| 逻辑字段 | 界面形式 | 默认与可选值 | 排版约束 |
|---|---|---|---|
| `seal.enabled` | 专属印记开关 / “盖上它的印记”动作 | 新作品默认关；有已确认资产才能开启 | 不盖也能保存和导出，不是打卡完成条件 |
| `seal.style` | 两个真实缩略图 | 朱印 `vermilion` / 压印 `emboss`；可记住该宠物最近款式 | 复用已有资产；不调用图像模型；不新增蜡封等未批准范围 |
| `seal.placement` | 版式安全位置选项 | 默认右下，可选左下；其他位置由模板明确提供 | 只在安全位置，不覆盖正文、健康值、页码或宠物脸 |
| `seal.size` | 小/标准两档 | 默认标准；按模板画布比例计算 | 不让印记变成第二个视觉主角 |
| `paper.ruleLines` | 正文横线开关 | 照片明信片、信纸默认开；其他按适配表 | 是正文基线下的信纸横线，不是所有 UI 文案和字形的下划线 |
| `paper.illustration` | 小插画样式选择 | 默认无；窗影/植物线描/明信片线饰等互斥选择 | 每页最多一个主要装饰主题，已有印记不再叠大量爪印 |
| `paper.texture` | 纸纹开关 | 模板有合格本地资产时可默认开，否则关 | 低对比，不能牺牲正文可读性；不复制虚假纸纹噪点到宠物照片 |
| `paper.photoFrame` | 相框样式选择 | 无/细边/相纸边；按模板支持项 | 不强制给所有照片套宽灰底，不重裁或拉伸原图 |
| `paper.footerBrand` | 小品牌标识开关 | 默认关 | 不加二维码、付费提示、账号信息或巨大水印 |
| `paper.pageNumbers` | 自动状态说明 | 单页不显示，多页显示当前页/总页数 | 与真实导出页序一致；不受品牌页脚开关控制 |

### 5.1 正文横线

横线按最终文字测量后的行来画。1080 宽成品的起始测试参数：正文可从现有约 44–48 px 范围检查；线位在实际基线下方约 0.20–0.28 em，细线约 1–2 px，颜色使用低对比品牌中性色，最终以手机成品可读性验收。

- 线不能穿过中文字形、英文字母下伸部、emoji 或行内标点。
- 标题、姓名、日期、健康数值和 UI 按钮不默认套正文横线。
- 换行、分页、改字号、开关模块之后重新计算，不使用一張固定间距背景图硬对齐文字。
- 用户关闭正文模块时，相应横线一起移除。空白装饰信纸线只能在明确支持的模板里作为独立背景出现，不能假装有正文。
- 同一段用户内容不为迁就横线而丢字、自动缩成小字或删段。

### 5.2 互动性的边界

互动发生在 App 编辑与预览中，导出的 PNG 是静态成品。

本轮实现三个有用动作即可：

1. **盖章**：点“盖上它的印记”，在安全落点短暂落印；可撤回、切朱印/压印；结束状态写进作品配置。
2. **选图案**：点装饰缩略图更换同一位置的线描/窗影等主题；不每次随机改变构图。
3. **调纸面**：横线、相纸边、纸纹开关即时反映在真实成品预览。

不做无限漂浮、闪烁、自动播放声音。系统减少动态效果时保留最终静态状态。动画未结束也不能阻断记录保存；导出使用稳定结束态，不截图动画中间帧。

装饰优先使用已有/新增的本地可复用程序化资产；本文件不要求调用生图、购买模板或引入新的图像服务。不得用通用猫狗图替代用户真实宠物印记。

## 6. 模板注册与基本适配

复用已有六种 ID，增量增加日常记录卡。新样式使用新模板版本，旧作品继续按旧版本与快照渲染。不要假定当前最新版本一定是 V3，也不要直接覆盖同 ID 的旧布局函数。

| 简称 | 产品名称 | ID 处理 | 比例/导出目标 | 最低成品条件 |
|---|---|---|---|---|
| 照片 | 照片明信片 | 复用 `day`，新版本 | 3:4，1080×1440 | 1 张用户选定照片；或明确切入已有肖像变体。关闭图片后改选文字模板，不保留空大图框 |
| 日常 | 今日记录卡 | 新增逻辑 ID `daily_record`，先查是否冲突 | 3:4，1080×1440，可分页 | 至少一个有内容的正文/健康模块；身份、日期、印记本身不算完整记录内容 |
| 短句 | 一句话 | 复用 `quote`，新版本 | 1:1，1080×1080 | 一段用户明确选择的短句；长文改模板或由用户选节选，不自动裁切 |
| 信纸 | 写给你的信 | 复用 `letter`，新版本 | 3:4，1080×1440，可分页 | 至少一句用户正文；称呼和署名可选 |
| 习惯 | 它的小习惯 | 复用 `habit`，新版本 | 3:4，1080×1440 | 一项用户确认的习惯/偏好描述或明确选入的相关片段 |
| 那天 | 那一天/时间标签 | 复用 `date`，新版本 | 1:1，1080×1080 | 一项有明确来源的事件日期/模糊日期描述，并有标题、文字或照片中的至少一种；书写日期不可冒充事件日期 |
| 拼贴 | 几个片段 | 复用 `collage`，新版本 | 3:4，1080×1440 | 2–4 张用户明确选择的不同照片；一张图不能自动复制补满 |

照片明信片与日常记录卡是新增统一记录体验的两个主要方向。其他模板不是换背景色；应有不同的主视觉、正文关系与信息容量。

## 9. 怀念模式的覆盖规则

模板支持矩阵是能力上限；怀念模式再施加一层更克制的默认策略。

- 继续使用同一记录/素材访问能力，旧陪伴内容不复制成另一套遗失关联的资料。
- “写给你 / 一段回忆 / 看看回忆”是主要方向；制卡不是每日任务，不触发连续打卡或奖励庆祝。
- 普通怀念制卡默认不出现健康模块；不自动读取临终记录、病灶照片、药物说明。
- `日期` 默认关；主动开启时明确选择“这件事的日期”或“写下这段话的日期”，允许模糊或未知事件时间。
- 不自动填离世日期、离开天数、天堂/轮回图案，不替用户作宗教或情感表达。
- 朱印和压印都保留，用户自己选，不把“压印才适合怀念”写死。
- 用户主动打开某条历史健康记录并选择“按这份记录制卡”时，可以使用日常记录卡。必须逐项选择，保留原事件日期并标注历史主人记录，绝不显示成“今天健康状态”。
- 从陪伴切到怀念不改变旧作品。新作不自动继承上一份健康卡的公开选择；历史作品重新导出仍按原快照，不偷换成新模式默认。

## 10. 开关状态机、模板切换与冲突处理

### 10.1 不能只存一个 showHealth 布尔值

至少区分：

| 概念 | 建议值 | 用途 |
|---|---|---|
| 用户意图 | `auto / show / hide` | 尚未选择、明确显示、明确隐藏；切模板不能抹掉明确选择 |
| 实际状态 | `visible / hidden / empty / unsupported / needsReview` | 告诉用户为什么当前没有显示 |
| 选择范围 | 来源 ID、字段路径、版本、必要时文字范围/照片 ID | 避免新记录或不同照片被意外加入 |
| 渲染状态 | preparing / rendering / ready / failed 等现有状态 | 与内容选择分开，渲染失败不能清空用户开关 |

计算顺序：

1. 检查账号/宠物/来源归属。
2. 应用模板能力与当前模式限制。
3. 应用用户本作品内明确选择；敏感内容只接受本作品明确选入。
4. 未明确选择的普通字段按模板/预设默认值处理。
5. 检查真实来源、去除同来源重复、应用版式容量及必要说明。
6. 得到显示内容后测量排版，再产生预览。

用户选择 show 但模板不支持时，保存其意图并返回 unsupported；不能改为 hide 后假称用户自己关闭。用户选择 hide 时，切模板、换纸纹、换印记或异步返回都不能把它重新打开。

### 10.2 不能静默丢内容

出现模板不支持、照片不足、文字溢出、健康项超额或私密内容尚待确认时，可以展示带明确提示的临时预览，但必须在最终存作品/导出前解决：

- 改用适配模板；
- 使用该模板明确支持的分页；
- 用户主动从本作品移除某项；
- 用户自己选择节选或补充必要素材。

不能用自动缩字到不可读、正文省略号、只留前三条、复制照片补格、AI 自动缩写等方式掩盖问题。列表缩略图可以截断预览文字，但真实导出不得静默截断。

### 10.3 恢复和联动

- 同一作品的设置随草稿恢复，包括选中字段、选图顺序、裁剪、印记、文字来源。
- 不把上一只宠物或上一账号的偏好应用到当前作品。
- 敏感项目选择不作为跨作品全局偏好记忆；普通纸面和印记风格可按账号/宠物记忆。
- 原记录更新后，编辑中的作品提示来源已变更；用户可使用当前选定快照或刷新来源。刷新会改变字段值时，旧预览和确认失效，需要再次看到实际成品。
- 旧保存作品保留旧名字、旧文本、旧印记和旧模板。重新导出不自动更新；“按最新资料制作新版”另存新作品。

## 11. 隐私、原文与导出数据边界

### 11.1 名字与印记

`显示宠物名字` 关闭后，系统自动排入的名字必须同步从标题附文、页脚、印记名字圈、自动图片说明等位置移除。

如果印记图片已经把名字画死在像素里，需要使用本地不含名字的版本或明确提示用户移除/重制无名字印记。不能只隐藏页首文字，却仍在红戳上露出同一个名字。不得自动更改用户原文，也不能承诺匿名：用户照片、正文中手动写入的名字仍需用户自己检查。

### 11.2 渲染只接收显示内容白名单

不要把整份日常记录对象直接交给绘制器，然后仅依靠 CSS 隐藏字段。

建议流程：

`原始记录 → 按作品配置提取显示白名单 → RenderPayload → 测量/布局 → PNG`

- 不显示的独立健康字段、私人备注模块、未选照片、账号令牌不得进入 RenderPayload。
- 关闭健康模块不是自动去敏：用户主动选入的生活正文、标题、照片本身可能仍含病情或身份信息。不可声称“已自动隐藏全部健康/身份信息”，也不擅自删改原文；最终预览说明请检查所选文字与图片。
- 私有来源记录可以按原机制保留；新作品显示快照尽量只保存选中内容，编辑关联使用最小来源引用，避免另存一份未选择的私密全文。
- 缩略图、预览、真正导出都读取同一份显示快照与版本。切换开关后使旧缓存失效，不让“预览隐藏了、保存的还是旧图”。
- 文件名使用安全的作品标识或普通日期，不自动写入病情、用药、用户姓名；不向图片元数据塞源记录、位置、账号和隐藏字段。
- 删除原记录/独立作品遵循已有明确提示和清理契约；不得以本文件为由删除用户原资料或冒称能撤回已保存到系统相册的图片。

### 11.3 润色与问诊不串用

只有生活/信件/用户选定的展示正文可以使用已经明确采用的有效候选。采用不代表改写健康原始事实；来源原文始终保留。

卡片切换、横线、插画、印记、预览、导出均不得请求 DeepSeek 或图片模型。点击润色仍是独立的授权动作，沿用主任务中的服务修复与限流要求。本补充规格不把已有归属校验失败伪装成已经解决。

  presentation: {

`resolvedVisibility` 与冲突提示按当前来源、配置、模板实时派生；不要把渲染失败误存成用户选择隐藏。缓存键包括账号/宠物作用域、模板版本、选定内容/素材版本、裁剪、全部可视配置和布局版本；不含明文私密资料的可外露文件名。

## 13. 与打卡激励的关系

本表负责卡片展示，不把“盖章”“公开健康数据”“制作作品”设成有效打卡的条件，也不以开关数量计算奖励。

主任务需要同步检查旧奖励代码是否仍只统计 `life/current`，排斥只有健康记录的真实日常记录；不得声称改了首页名称就已经完成融合。新健康/日常有效日规则应在主任务中集中定义并测试，按真实主动记录、同日去重、无连续惩罚处理，不按病情好坏、医疗行为次数或公开多少信息奖励。

本文件不擅自调整已有 1/3/7 阈值、会员、形象生成次数，也不回溯重复发奖。健康信息缺失仍未知；仅保存照片也可以是日常记录，但不能显示成“所有健康项都已记录”。

## 14. 具体例子：同一条日常记录，三种作品

以下为虚构测试数据，不是用户宠物的真实健康情况：

- 日期：2026-09-29。
- 用户记录整体状态：平稳。
- 饮食：食欲比平时少一些。
- 体重：4.2 kg，测量日期同上。
- 手写观察：下午吃得比平时少，暂时没有其他观察。
- 生活片段：傍晚又在窗边坐了一会儿。
- 照片：用户主动选的窗边生活照片。

| 成品 | 开启内容 | 关闭内容 | 效果与不变项 |
|---|---|---|---|
| 生活明信片 | 照片、生活片段、名字、日期、横线；主动盖朱印 | 所有健康、手写观察、额外备注 | 干净的生活作品；食欲与体重仍在原记录、仍可供授权问诊取材 |
| 今日记录卡 | 名字、日期、饮食、体重、手写观察；可选小照片 | 未选择的其他健康项与主人心情 | 只显示真实已选观察，并带日期/主人记录节选说明，不出现“全面正常” |
| 后来想起它的一封信 | 用户另写的信、明确称呼、主动盖压印、正文横线 | 自动健康插入、死亡倒计时、未授权旧照片 | 由用户自己的话构成，不把当天病情自动拼进怀念信，不伪造宠物回信 |

第二张卡里“整体状态平稳”和“食欲偏少”可以同时是用户不同原始观察；不能为了显得一致而改写任一个。是否展示整体状态由用户决定。

## 15. 必测验收用例

### 数据与来源

1. 同一记录同时有健康和生活内容，关掉健康展示后，原记录字段及问诊取材结果不因卡片开关改变。
2. 只有健康记录也能手动制作日常记录卡，无需再编一段生活故事。
3. 只有生活照片不产生“健康正常”、不补未知健康项目。
4. 只有“饮食”标签没有结果值时，不显示“食欲正常”或捏造数量。
5. 旧单一手写字段不被复制成三段内容；不同日期相同数值不被误去重。
6. 旧状态主体不明时不冒充主人心情或医学健康结论。
7. 原记录修改后，编辑中作品提示来源变化；已保存作品保持原快照，另存新版才更新。

### 开关与隐私

8. 关闭健康总开关不丢本作品子项选择；重新开启不扩大为全选。
9. 开启健康项目不自动选择用药、异常、预防照护或全部附件。
10. A 模板明确关闭名字/健康后切 B，再切回 A，明确关闭仍有效。
11. 关闭自动宠物名字后，印记名字圈和系统页脚同步不显示；正文/照片内姓名残留准确提醒，不假称匿名。
12. 隐藏字段不进入 RenderPayload、导出文件名与图片元数据，旧预览缓存不被再次导出。
13. 图片全部取消或所有主体内容关掉后，阻止无意义成品保存，并提供选内容/换模板操作，不自动填示例。
14. 草稿恢复与账号/宠物切换后，原开关、照片与候选不串用。
15. 新作品不继承上一作品对健康或私人备注的公开选择。

### 模板与排版

16. 照片明信片选四个健康项目时不默默丢掉第四项；明确解决后才导出。
17. 拼贴只有一张图时不复制补格，给选图或换模板动作。
18. 短句输入长文时不静默裁字、不自动请求模型摘要；用户自己选节选或换模板。
19. 关闭正文后对应横线消失；中英文、emoji、多段长文的横线不穿字，分页后行线仍对齐。
20. 印记不盖脸、正文、体重值、必要日期或页码；装饰切换不改变原照片和记录。
21. 动态盖章结束态与真正 PNG 一致；减少动态效果仍可静态盖章、撤销和导出。
22. 源图比例、全身图、无照片纯文字、极短文本和长信都检查实际导出，不以代码存在代替视觉检查。
23. 单页没有 1/1，多页顺序页码正确，隐藏品牌页脚不隐藏健康来源说明或页序。
24. 原 V1/V2/V3 等已保存作品按各自真实版本恢复，不偷套新开关或新名字。

### 怀念与成本

25. 怀念新作不自动显示健康模块、临终材料或离开天数；主动打开历史健康制卡保留正确事件日期。
26. 切换开关、模板、纸纹、印记、预览与导出，文字模型调用数和图像模型调用数均不增加。
27. 新制卡交互不变更会员、生图账本和既有记录保存结果；不盖章也能正常保存。
28. 日常记录成功、作品存册成功、下载发起、相册实际成功分别报告，不混为一次成功。
