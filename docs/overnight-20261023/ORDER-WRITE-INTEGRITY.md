# 会员订单写入与支付准备确认

2026-10-23 11:20。本轮只有源码和本地服务替身，没有真实下单、支付、云调用、配置读取或部署；没有开启支付开关。

订单模块原先对查询仅判断data数组，插入忽略返回值，支付准备拿到updated=1就返回拼出的记录。错误回执、未落库的成功计数和损坏金额可能继续进入支付准备。已增加严格查询、单条记录自身ID、归属、金额/币种/权益、时间和支付尝试字段校验。

正常插入需要匹配的ID回执，再回读持久化订单；准备支付需要明确更新结果，再回读同一笔订单及商户绑定。结果未知或自相矛盾时停止，不调用支付服务。已写入但回执异常的订单，后续相同请求会恢复同一笔；准备回执异常的重试沿用原支付单号，不再次写准备状态。

并发唯一ID竞争以已经持久化的第一笔订单为准，不因不同服务器时钟刻度或后续目录快照而改价。已准备的订单同样遵守原有30分钟有效期检查。数据库传输异常统一映射为安全订单错误，不透出原始诊断。

## 不变项与未完成项

服务端批准的目录、售价、会员档位、10次生成额度、时长范围及默认关闭规则未改变。历史已保存订单仍使用自己的价格和商户绑定，不用当前目录重写。

实际数据库SDK、唯一索引、官方支付沙箱、真实签名通知和云端版本仍未验证。代码中旧支付尝试保留原商户，而支付入口使用当前通道的配置目录；通道轮换后两者一致性还需独立处理和验收，本轮未改通道路由。订单回执通过也不证明支付成功或会员激活，后续必须依赖验证后的通知与权益记录。
