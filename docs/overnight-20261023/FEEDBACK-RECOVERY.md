# 留言提交：回执恢复与失败保护

本轮修改已在本地和真实 H5 验证，尚未部署云函数。没有向真实开发者信箱发送测试留言。

## 已复现的问题

- 数据库已写入、随后回执丢失时，接口返回失败，页面断言“没有送达”；同日再次提交只得到重复错误，不能正常完成页面流程。
- 数据库返回缺少 data 等异常结构时，原实现可能当作没有记录继续写入。
- 错误文字中只要出现 `_id` 就可能被当作重复提交，错误宣称“已经收到”。
- 两个请求同时创建限流窗口时，一个请求初次更新未找到窗口，随后读到另一个请求刚创建的窗口，就被误判为超限。

## 现在的行为

1. 已存在的留言必须同时匹配确定性ID、调用者身份摘要、内容指纹、已提交状态和有效创建时间，才能恢复成功回执。
2. 新写入异常时，只读取一次该记录确认结果；不自动重复写入。确认不了就返回安全503，页面提示无法确认、保留内容后重试。
3. 正常同日重试直接返回原回执，不再次占用留言限额。已确认留言中的原图片无需重新验证过期上传票据；不同内容的新提交仍必须经过完整图片归属验证。
4. 读结果、限流更新结果和新建回执必须有合法结构。正常空数组仍表示不存在；异常结构不能冒充空表或写入成功。
5. 限流窗口创建竞争使用带上限条件的原子递增补查，不放宽原来的小时、日、网络与全局限额。
6. 账号服务暂时故障返回503，已知身份失效保持403。原始数据库或网络错误不返回给页面。
7. 留言页分类按钮至少44px、提交按钮至少48px，文字接入现有字号倍率；360宽度和1.3倍字体已实测，首页锁定区域未修改。

## 明确边界

去重仍沿用既有“北京时间当天 + 服务端身份摘要 + 内容指纹”，没有增加新数据库集合或迁移。跨日重试、游客网络身份变化仍可能形成新留言；这不是跨日、跨设备永久幂等。并发请求在最终写入前可能分别占用限额，暂不做自动退回，防止不确定结果下扩大放行。

未实施开发者处理后台、工单状态流转、通知、自动回复或真实上传。真实截图上传、云环境部署和Android本地媒体清理仍待集中验收。

数据库单条新增回执字段和条件更新行为依据[DCloud传统云数据库API](https://doc.dcloud.net.cn/uniCloud/cf-database)核对；云端实际响应兼容性仍待部署后验证。
