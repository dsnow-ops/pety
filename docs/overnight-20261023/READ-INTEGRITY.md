# 记录读取与覆盖保护：2026-10-23 04:53 阶段

## 已复现的问题

创作存储原先用 `{...empty(), ...(raw || {})}` 读取。字符串、数组或错误类型的分区会被当成空记录或不完整对象，后续保存可能覆盖原始资料。旧日历读取也会把错误容器降为 `{}`，保存无法区分“没有记录”和“资料没有正确读出”。本轮测试先复现这两种缺口，再修复。

## 实际修改

- 创作容器检查版本、各分区的对象/数组类型及记录条目。无法读取或版本不支持时拒绝写入，不自动清空、不做猜测迁移。缺少可选分区和额外元数据保持兼容。
- 旧日历写入必须先通过严格读取；日历编辑器、制卡页和明细页采用严格模式。旧概览调用仍保留原有非抛错读取契约，避免因为一个错误容器打断整个首页初始化；这些概览不是本轮新增错误提示的验收范围。
- 册页、日历、文字编辑器和制卡页显示明确读取失败面板，提供重试；异常时隐藏编辑内容，不显示“空册页”。
- 日历打开之后才出现资料异常，主记录保存也会在写入前被拦下，当前输入保留。制卡途中读取失败保留内存中的未保存版式，重试不会重新初始化并丢弃它。
- 统一错误面板的大字体和窄屏间距；四页均实际验证到1.3倍字体。首页主视觉三个源码文件未改动。
