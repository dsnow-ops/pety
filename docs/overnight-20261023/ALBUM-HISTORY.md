# 册页长期记录分页与旧照片找回

本轮修复两处实际浏览问题：原来的“继续查看”持续增加请求条数，但查询单次最多返回1000条；照片页先取前30条文字/照片混合记录，再提取照片，导致更早的照片需要不断展开文字记录才能出现。

## 现在的行为

- 记录与照片按每页30条来源记录浏览，提供上一页、下一页、查看末页和回到第一页，显示当前页码及总数。
- 超过1000条后仍可以继续访问旧记录，每页不累积渲染全部历史。
- 照片页先筛出当前账号、当前宠物可显示的生活照片记录，再分页；月份目录也对应含照片的记录。照护附件和用途未知附件继续留在原记录中。
- 搜索、筛选及切换视图返回第一页；从原文返回册页保留阅读位置；删掉末页内容后自动落到剩余的最后一页。
- 照片选择可以跨页保留，导出忙碌期间不能翻页。原图下载仍只包含明确选中的照片。
- 无照片的筛选范围有明确提示与清除入口，选择月份后继续停留在照片视图。

- 作品页取消原先4件/100件的展示截断，按每页4件浏览所有已保存作品。查找真正匹配作品标题和已保存文字，无匹配时可以返回全部作品；大字体同时作用于作品标题和分页按钮。封面只渲染当前页。

## 保留的失败与限制

[修复前5项测试](album-pagination-before/tests.tap)均失败。`album-pages-h5-1`因受限环境无法启动Edge而停止；第二轮已通过1105条翻阅，但脚本错误假设从原文返回必在第一页，定位超时；第三轮修正该假设后完整通过。增加作品用例后，第四轮脚本未先从作品预览点击“返回文字”，第五轮又误把已展开的搜索框关闭；这些定位假设已修正，第六轮10组完整通过，旧失败结果全部保留。`local-14`的唯一失败为回环网络被环境拒绝，获准本机测试后`local-15`全部通过。

这些资料都是明确标注TEST的本地合成数据。未触碰用户原记录；未新增云同步、换机恢复或视频批量下载。37页操作耗时只代表本次桌面隔离浏览器，不是Android性能承诺。作品分页和查找也已加入本轮综合验证，未改写原作品快照。

复现：`node scripts/verify-overnight-album-pagination.cjs <新的证据目录名> round-22`。脚本只启动本机服务和独立浏览器，外部网络全部阻断。历史`verify-life-remaining.cjs`沿用其旧版“继续查看”验证方式，不作为本轮分页的验收脚本。
