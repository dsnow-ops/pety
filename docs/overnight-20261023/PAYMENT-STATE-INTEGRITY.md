# 支付状态与权益周期的一致读取

2026-10-23 11:34。本轮纯后端源码与本地替身，没有真实支付、退款、云调用、开关修改或部署。

支付状态读取现在区分“合法空结果”和“数据库读取失败”。错误码、明确失败标记、空占位行、重复行和错误文档ID均停止，不再伪装成未支付、等待激活或已生效。支付回执必须对应订单的金额、币种、档位、时长、额度、支付尝试和交易编号，时间字段也必须有效。

支付状态与实际付费会员读取共用权益周期检查。损坏的撤销记录、撤销凭据与仍标记生效的周期矛盾、同时出现两个当前生效周期都会报告状态不可用；不会随意选一个周期授权。合法的提前退款记录可以在周期尚未建立时保留撤销结果。数据库原始异常映射为安全状态错误。

共享旧会员查询也补上ok=false、success=false检查，避免支付状态拒绝了同一份错误回执，旧会员入口却仍然接受。

- 最终新增12组；其中正常未开始、待确认、待激活、排期、生效、过期、撤销和提前退款共8种结果，与修改前代码逐项等价。
- [支付与权益完整本地专项](payment-state-regression-final.tap)：66/66，覆盖实际模块组合及测试替身，并不是真实支付验收。
- [整体相关回归](local-49/results.json)：537/537，本轮纳入12项新增与3项已有支付状态测试。
- 旧支付状态测试补齐正式回执要求的档位、时长、额度、付款时间和退款凭据；传输异常断言改为安全错误码。没有降低正式数据校验来适配旧替身。
- 首页锁定文件未改；本轮没有前端修改，也没有新增H5、App安装包或真机结论。

## 边界

这轮修复读取和显示/授权的一致性，没有完成支付通知入库、权益激活写入及撤销写入的全部异常回执审计。实际数据库SDK、官方签名通知、唯一索引、真实支付/退款及通道轮换仍需隔离环境验收。读取到不一致资料时停止授权，不擅自修复或删除真实订单。

售价、档位、时长规则和每期10次生成额度未改；不能把通过的本地测试数量当作正式支付可以上线。
