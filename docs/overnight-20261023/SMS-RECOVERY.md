# 短信预算与不确定发送回执

本轮继续检查短信链路，发现预算查询/更新接受异常结果、损坏计数仍可能参与事务，以及发送接口的返回值被忽略的问题。以下均为本地源码修复，未发送真实短信，未修改真实验证码和预算记录。

## 已修复

- 预算普通查询要求零或一条合法记录；错误码混入数据、空元素、多条数据不被当作空表。
- 首次创建必须有对应ID回执；不确定时直接停止，不重试写入。
- 事务中的记录必须属于预期ID，计数/版本/冷却时间必须是合法非负整数；拒绝溢出前的计数，避免长期运行后数值失真。
- 每次事务更新必须明确更新1条；缺失、字符串数字、矛盾字段、错误码或0更新均回滚并报告服务不可用，不伪装成限流。
- 发送接口只有明确成功回执才返回成功；回执不明报告“暂时无法确认短信发送结果”。此时保留已预留预算和可能已发送的验证码，不自动再次发送。
- 手机、IP和全局上限、60秒默认冷却、图形验证码及用户同意流程保持原有规则。

## 验证

- [修复前17项结果](sms-recovery-before/tests.tap)：既有11项通过，新增6项失败，已保留复现证据。
- [实际短信处理器与工具测试](../../tests/release-sms-budget.test.cjs)：修复后17/17通过；异常预算使发送次数与验证码生成数均为0；事务回滚后明确重试可成功一次；未知发送回执保留预算并阻止立刻重发。
- [local-11/results.json](local-11/results.json)：全部相关回归248/248通过，首页三个锁定源文件未改。
- [客户端短信专项](sms-client-regression/results.json)：图形验证码、输入保留、发送门槛与客户端冷却回归；真实云端与用户手机仍未验。

[DCloud短信API说明](https://doc.dcloud.net.cn/uniCloud/sms/dev.html)规定成功回执的errCode为数字0，并明确接口调用成功不等于手机实际收到短信。本轮保留这一差异，不把本地替身的成功视为真实送达。

## 部署与验收边界

修改包含公共模块`pety-auth/sms-budget.js`和`uni-id-co/lib/utils/sms.js`，需要在受控发布中一并检查部署版本。尚未发布，也没有测试真实OTP、短信收费、运营商延迟或手机接收；这些需与正式登录和单设备会话验收集中进行。预算事务的真实隔离行为仍需云端独立验证。
