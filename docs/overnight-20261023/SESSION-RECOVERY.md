# 登录会话的异常状态与回执保护

本轮在单设备会话源码中复现了实际问题：有效期缺失或为NaN时，普通大小比较不会判定过期；部分票据消耗、续期、注销写入没有核实回执，可能返回假成功。修改位于`uniCloud-alipay/cloudfunctions/common/pety-auth/sessions.js`。

## 已修复

- 当前会话必须具备正确归属、版本、哈希和非负整数有效期；缺失、NaN、字符串时间不再成为无限有效会话。
- 普通查询与事务查询先检查服务错误；带错误码的数据不能作为有效会话使用。单文档普通查询拒绝多条、空元素等异常形状。
- 会话和登录挑战创建必须有对应ID回执；未确认写入不向客户端释放挑战。
- 接管票据的有效期、使用标记、预期版本和官方令牌失效时间必须合法。票据消耗未确认时回滚接管，不签发令牌。
- 续期未确认时回滚该事务中的会话写入；取消和注销回执不明时不报告成功，也不自动重复写入。
- 官方令牌签发返回必须包含非空令牌和未来有效期；异常结果不释放成功凭据。仍保留签发后再次验证当前会话的竞争保护。

## 证据

- [修复前18项结果](session-recovery-before/tests.tap)：原有10项通过，新增8项失败。
- [单设备会话测试](../../tests/single-session-v1.test.cjs)：修复后18/18，包括并发接管、旧票据重放、过期票据、迟到注销、配额与接管事务冲突、异常有效期和写入回执。
- [local-12/results.json](local-12/results.json)：加入完整会话套件后，相关回归266/266通过；首页锁定文件哈希未变。
- 检查当前`uni-id-co/module/utils/pety-session.js`仍使用官方`uniIdCommon.createToken`签发令牌，没有新增自制令牌或跳过官方验证。

## 边界

这些是内存事务替身中的行为验证，不能证明云数据库真实隔离级别和手机上的登录体验。本轮未改变staged/enforce/deny配置，未强制上线单设备模式，未注销真实用户，未部署公共模块。

令牌签发在接管事务提交之后发生。若签发返回异常，已经提交的接管不会被猜测性撤回：旧会话可能已经失效，用户需要重新完成明确的登录确认。这一恢复限制仍存在，不能声称所有异常都会保持旧设备登录。

正式验收需集中测试A/B两台设备、旧设备刷新与返回、后台切换、接管时网络中断、过期挑战、注销回执丢失；在同一明确版本的云函数与App上完成，不能用H5或本地MVCC替身替代。
