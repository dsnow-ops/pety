# 付费调用前的成本预算回执检查

本轮发现并复现：首次创建预算记录后，代码没有检查数据库回执；更新计数使用宽松的数字转换和字段兜底。缺失回执、错误码混入成功字段、相互矛盾的计数结果可能被当作已完成记账，继续进入付费调用。

已修改 `uniCloud-alipay/cloudfunctions/common/pety-auth/cost-budget.js`：

- 单文档查询必须是零或一条完整记录；错误响应、空元素、错误归属、非法计数不被当作“没有记录”。
- 首次创建必须收到与预期记录ID一致的成功回执。
- 更新结果必须包含明确的整数0或1；多个兼容字段同时出现时必须一致。带错误码、字符串数字或缺失计数均拒绝。
- 写入结果不明时不重写、不退款、不调用模型。仅明确的重复创建或零更新允许有限重读；最终确认计数到顶才返回超限，否则返回预算服务不可用。
- 保留已有账号/全局双重上限及保守记账：全局预留失败不撤销已占用的账号次数。没有改变会员权益或用户成功次数规则。
