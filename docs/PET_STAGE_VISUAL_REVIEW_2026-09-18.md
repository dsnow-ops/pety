# 归爪：统一影像舞台验收（2026-09-18，收口于 09-19）

## 结论与范围

已将首页主路径切换为「已确认高清 master + 统一影像舞台」。已在连接的 Android 真机验证现有比格犬、长毛白猫两只真实宠物；图像加载、背景取色延展和切宠均有效。此结论不是 ImageGen 合成图或 fixture 替代真机。

这轮遵循新的路线要求：透明角色不再是普通展示的必备前置条件。保留透明资产能力，但首页不再自动提交或轮询可选角色生成任务。没有改云端模型、真实 config、uni_modules，没有 commit/push/reset/stash。

本轮没有解决或证明所有任意实拍背景都能无缝融合。复杂背景被拒绝边缘融合，保留清晰原图；它是功能降级，不是同等审美验收通过。没有真实橘猫生成结果，不能把合成颜色测试写成橘猫视觉已验收。

## 根因与最终方案

旧版把白色信息卡、右侧独立矩形图片、悬浮角色容器组合到一起。三者的背景、尺度和阴影语言互相冲突；单独改圆角或加淡出无法解决结构割裂。

新版是一个整体舞台：左侧信息、按钮和右侧完整主图共享背景。图片保持 aspectFit 与原分辨率，不拉伸、不裁耳朵、不滤镜软化毛发。原图已有的地面明暗负责安置宠物，外卡只保留轻阴影。首页图像区约 65%，信息区约 35%，主卡 440rpx 高。工作台继续固定方形容器，与首页共用同一组件、取色逻辑和边界规则。

第一轮「整张图边缘平均成一个底色」在实图预览中被否决：纵向明暗不连续，仍有明显方块。最终按左右边缘分别采样、分九段延展纵向明暗。没有采用大范围羽化、模糊背景、重阴影、伪透明或改变整页饱和度。

## 色调和边界规则

- 使用 48×48 低分辨率采样副本；显示图仍是原始高清 master。
- 外围三像素参与背景判定，忽略 alpha 小于 245 的样本。
- 三通道中位数最大差必须小于 48，最小通道大于 115，样本偏差中位数小于 20，才启用融合。
- 左右各两列、九个高度位置产生各自背景延展；不会把整个页面染成原图颜色。
- 页面只允许三种近中性品牌底色：sand `#f5f2ec`、mist `#f1f3f2`、stone `#f4f3ef`；按钮固定低饱和橄榄色。
- 只有通过上述背景门槛才使用图片最外侧 2% 的薄过渡。它只缓解边界插值差，不承担抠图工作；主体无 blur、无颜色滤镜。
- 深色、鲜艳或复杂背景关闭边缘融合，采用中性舞台与完整原图。不会强行把粉色沙发或绿色草地扩散到页面。

这不是全量图片语义识别，也不是粉边分割检测器。合格棚拍图可自然延展；非标准背景若未来必须达到同等融合质量，需要在资产生产层规范背景，不能继续在显示层加滤镜掩盖。

## 资源与稳定性

首页优先使用当前 pet 已确认 master。master 文件 ID、pet ID 和实际显示资源共同构成身份；临时 URL 只是可刷新的地址。master 存在但 URL 未就绪时等待同一资产，不先闪另一张衍生图。

没有 master 时仍保留原有同源合格衍生资产候选和 placeholder，未经质量验证的衍生图不能成为主图。cutout/job 失败不再阻断 master 展示，正常 master 路径的 fallbackReason 为空。

组件对 load/error、取色、尺寸测量均检查当前身份、URL、请求 epoch 和卸载状态。切宠清空旧图和旧配色；同一文件 URL 更新可暂留已加载内容。调色缓存最多 40 项，按不可变资产身份隔离，不按 URL 判断是否同一宠物。

## 审美结论与前后对比

最自然的实证是白猫首页：旧截图中，猫在右侧独立米色矩形里，矩形左边与白卡形成分界，按钮像另一套组件。新版将原图左边的石色明暗贯穿信息区，右侧保持毛发、眼睛和尾巴清晰；原有地面阴影安置主体，按钮与文案有稳定的左侧留白。用户无需靠模糊去理解边缘，整卡具有共同的光线关系。

我认可已验证的标准棚拍主图达到本轮「统一、安静、可交付」方向：主体完整、视觉中心明确、没有新增粉边与大面积灰雾，卡片和信息不是分裂结构。它比旧版成熟的原因是统一构图和明暗，而不是特效变多。

没有把「超过所有成熟竞品」当作已经证明的事实。当前妥协是采用摄影舞台，而非宠物真正越出卡片的透明角色体验；这是本轮优先保证各种合格 master 稳定、清晰呈现的路线选择。

尚未达到最高标准的边界：复杂原始背景无法同等无缝；没有真实橘猫/深色狗生成图覆盖；工作台原生结果页缺少本轮截图；首次取色完成前可能有短暂中性底色变化。上述边界不可被测试通过数掩盖。
