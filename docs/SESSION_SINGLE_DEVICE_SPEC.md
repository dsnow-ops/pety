## 身份与入口盘点

当前依赖是 uni-id-co 1.1.28、uni-id-common 1.0.19、pety-auth 1.0.0。继续由正规登录验证密码、验证码或第三方身份；不把设备号当凭证。

## 会话契约

`pety_active_sessions` 每个 guizhua + UID 一个确定 ID；`version` 单调递增，256 位随机 secret 仅摘要落库。证明与正规 token 对应的 UID、产品和版本共同校验。确认票据也是随机数，仅摘要入库，绑定验证账号、有效时间、当时会话版本和密码失效时间。比较版本与票据消费同事务，B/C 并发只允许一个胜出；落败者必须重新验证和确认。

客户端显示“继续登录将退出其他设备；未同步的资料仍保存在原设备”。服务端确认返回 `petyIssuedToken`，刷新返回 `petyRefreshedToken`，避免 SDK 在页面取消/新登录后自行写入迟到 token；客户端仍按登录操作序号、旧 token 和证明检查后提交。

新请求先受理，已受理任务可完成；接管后旧证明不能再受理任务。生成请求在同一数据库事务检查会话、复核会员周期并预留原额度账本，接管写入同一会话文档产生冲突。额度仍按原 UID / 宠物 / 会员周期，不随设备或会话重置。实际云事务冲突码与重试行为必须在开发云复验。

## 本地失效处理

收到 revoked/required 时，先同步通知正在写作的页面保存草稿，再将原账号作用域设为 locked/ready=false，移除在线凭证，跳到登录页。原文、照片和作品均保留原键；不迁移到游客。迟到 A 错误不能锁住已接受的 B。用户可主动进入本机游客空间；只有重新登录原账号才能恢复其资料。前台检查只在已有新式证明时进行，不新增轮询。

## 部署与迁移——本轮没有执行

1. 确认一个可操作的**开发空间**及模拟账号；不能把 HBuilderX 当前绑定空间直接推断为开发环境。
2. 先建两张私有集合及唯一 `_id`，所有客户端 CRUD=false；确认事务、条件更新返回字段及跨集合提交能力。过期票据可经受控后台清理，不能影响业务资料。
3. 所有相关函数及公共模块一起更新，模式先 `PETY_SINGLE_SESSION_MODE=staged`；部署 uni-id-users 的关闭直读规则及新的资料读取接口，配套客户端一起验收。
4. **存储权限是严格模式启用阻断项**：在云控制台关闭客户端直接签发受保护存储 URL 的能力，验证 SDK/JQL/REST 不能用旧 JWT 绕过；改走所有者检查网关。原已签发 URL 可能在其有效期内继续下载，不能谎称立即召回已下载图片。历史原照片无正规持有回执时，先做受控归属迁移；本轮不凭本地声明认领文件。
5. 完整列出所有已上线客户端和函数版本，全部接入证明后，在开发云同一空间将入口统一切到 `enforce`。旧客户端缺证明应要求升级/重新登录，不能自动领取新会话。
6. 用虚构账号进行 A/B 登录、B 取消、B 接管、A 旧刷新、迟到退出、B/C 并发、受理/预留冲突、App/H5/小程序、断网、草稿归属和存储直连测试。此步骤当前待验证。
7. 出现严重问题切 `deny` 暂停相关在线操作，保留本机资料；严格上线后不能以回退为名恢复旧付费 token。

`staged` 明确表示未启用限制；不是防共享降级方案。当前没有修改任何真实环境开关、密钥、云数据或生产资源。

测试文件 `tests/single-session-v1.test.cjs` 使用生产会话实现 + 本地 MVCC 数据库替身，覆盖并发和失效契约；它不替代实际 uniCloud 双会话、短信、第三方登录、存储权限或支付联调。
