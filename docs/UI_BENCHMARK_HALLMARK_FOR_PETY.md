# Hallmark UI Benchmark for Lumière Pet

> 文档性质：纯 UI / 视觉基准分析与可执行重构策略  
> 参考项目：`hallmark`  
> 目标项目：《归爪 Lumière Pet》  
> 约束：提取设计语言与信息架构，不照搬页面、代码、主题或业务功能。

## 0. 结论先行

Hallmark 最值得归爪借鉴的，不是某一种配色、某张 Hero 或某个 CSS 效果，而是以下设计方法：

1. 先确定页面唯一主角，再组织其余信息。
2. 用字体、留白、细分隔线建立层级，减少卡片数量。
3. 每个页面只保留一个高视觉权重区域。
4. 用语义化颜色和间距变量维持一致性。
5. 动效有明确节奏，且每页最多使用少量核心动效。
6. 页面结构随任务变化，不把所有页面套进同一种卡片模板。

归爪应形成自己的视觉母题：

> 一只宠物、一个关系时刻、一项当下动作。

陪伴模式应温暖、清醒、有生活感；怀念模式应安静、克制、有微弱暖意。两种模式保持相同布局骨架，只切换语义、色温和节奏。

## A. 参考项目概况

### A.1 技术栈

Hallmark 当前仓库不是 React、Next.js 或 Tailwind 应用。其主要构成为：

- Markdown 设计规范与参考资料；
- 静态 HTML 页面；
- 原生 CSS；
- 少量原生 JavaScript；
- CSS Custom Properties 主题变量；
- 独立页面示例与截图资产；
- Python 静态服务器启动脚本。

因此，本分析不会建议把其 HTML/CSS 直接移植到 uni-app，也不会建议引入对应前端框架。值得迁移的是其设计决策方式、视觉变量结构和页面组织原则。

### A.2 页面结构

Hallmark 主站主要由以下层级组成：

1. 轻量顶部栏；
2. 单一高权重 Hero；
3. 主题或案例展示轨道；
4. 纵向内容章节；
5. 安装或行动区域；
6. 克制页脚。

每个章节通常使用“短标签 -> 标题 -> 正文/内容”的同轴结构，而不是把标签和标题拆到左右两列。不同章节的密度和留白有变化，不机械复用相同高度。

### A.3 主要组件类型

- 语义色彩与排版 token；
- 主题切换容器；
- 单焦点 Hero；
- 细边框内容带；
- 编辑式章节标题；
- 稀疏案例网格或横向轨道；
- 主次按钮；
- 状态标签；
- 轻量通知卡；
- 浮动导航；
- 模态框和下拉层；
- 有节奏的页面进入动画。

## B. 最值得借鉴的 12 个 UI 特征

| 特征 | Hallmark 的处理 | 归爪的可执行映射 |
| --- | --- | --- |
| 1. 单一视觉主角 | 每个 Hero 只围绕一个物体、人物或信息焦点展开 | 首页只让宠物成为主角；聊天页让对话成为主角；日历页让选中日期成为主角 |
| 2. 先选宏观结构 | 不把所有 brief 套入同一模板 | home、chat、profile、calendar 分别使用适合任务的骨架，不复用“标题 + 多卡片”万能模板 |
| 3. 语义化 token | 使用 paper、ink、rule、accent 等角色变量 | 归爪建立背景、表面、文字、弱文字、分隔线、强调色、危险色等稳定角色 |
| 4. 一主一辅配色 | 一个锚点色加一个稀疏强调色 | 陪伴模式用鼠尾草灰绿为锚点、陶土暖色为点缀；怀念模式用雾蓝灰为锚点、烛光暖色为点缀 |
| 5. 字体承担层级 | 展示、正文、微标签角色清楚 | 宠物名与关键日期可更有情绪；正文保持清晰；状态和辅助信息更轻，不依赖大色块 |
| 6. 留白有方向 | 空间围绕焦点组织，不是平均铺开 | 宠物周围留白更大，工具和次要信息压缩；不同页面不使用相同 section padding |
| 7. 细线代替卡片 | 内容组常靠 hairline 和背景带分组 | profile 设置项、calendar 信息、chat 辅助入口优先用分隔线和分组面，不给每项单独套卡 |
| 8. 不嵌套卡片 | 避免 card inside card | today panel 内不再放多张独立卡；聊天输入区不再叠多层玻璃容器 |
| 9. 微标签来自内容 | 标签用于类别、状态、步骤，不作装饰 | 只保留“陪伴中”“怀念模式”“今天”等真实状态，删除 SMART GUIDE、CARE、MODE 等后台感标签 |
| 10. 受控动效节奏 | 进入、按压、模态有各自时长；每页动效有限 | 页面一次进入、按钮按压、必要的内容切换即可；不让每张卡片都漂浮或发光 |
| 11. 导航几何稳定 | 导航状态切换不改变整体占位 | 未来 custom tabbar 高度与安全区固定，只改变当前项视觉，不引发页面跳动 |
| 12. 空状态指向下一步 | 空状态说明当前状态并给一个行动 | 没有记录时直接引导“记下今天”；没有电子形象时说明准备状态，不用大面积空卡占位 |

## C. 适用性与边界

### C.1 为什么适合归爪

#### 宠物天然适合“单焦点”

归爪不是数据仪表盘。宠物本身、宠物名字和关系状态应优先于健康分、记录数量、会员信息。Hallmark 的单焦点构图能帮助归爪停止堆叠功能卡。

#### 编辑感能降低工具感

清晰标题、短副文案、细分隔线和非平均留白，可以让档案、日历和个人页更像关系记录空间，而不是后台管理系统或医疗表单。

#### 受控颜色适合双模式

陪伴与怀念不需要两套完全不同的 App。通过相同语义 token 替换色值，可以在不改变布局的情况下切换氛围。

#### 克制动效更适合长期使用

归爪是每天打开的应用。短、慢、可预测的动效比持续流动背景和大量浮动元素更耐看，也更适合低端设备。

### C.2 哪些不适合直接迁移

#### 大型网站 Hero 不适合手机首屏

Hallmark 示例里的超大标题、左右分栏和网站级导航不应照搬。移动端首页需要更短路径、更稳定高度和更快到达核心动作。

#### 深黑技术主题不适合作为归爪主视觉

Lumen 类暗色科技风可为形象生成页提供“一束光、一个主体”的灵感，但星空、仪器、网格和强黑底会削弱归爪的生活温度。

#### Mono 标签不适合大量出现

英文等宽标签在设计展示站中有效，但在归爪会产生后台字段感。仅在日期、版本或必要技术状态中谨慎使用。

#### Web 浮动导航不能直接变成 App 导航

网页滚动导航依赖视口和滚动状态。归爪底部导航应遵循原生 App 的安全区、固定触达和稳定页面切换。

#### 主题展示能力不是产品功能

Hallmark 的多主题切换是设计系统展示能力。归爪只需要陪伴与怀念两种产品模式，不应增加用户可选皮肤系统。

## D. 归爪可复用设计语言

### D.1 颜色

颜色必须按角色使用，禁止页面自行发明近似色。

#### 陪伴模式

| 角色 | 建议值 | 用途 |
| --- | --- | --- |
| `page-bg` | `#F4F1EA` | 页面底色 |
| `surface` | `#FAF8F3` | 主要内容面 |
| `surface-muted` | `#E9E7DE` | 次级分区 |
| `text-primary` | `#292721` | 标题与正文 |
| `text-secondary` | `#69645B` | 副文案 |
| `rule` | `rgba(41, 39, 33, 0.12)` | 分隔线与边界 |
| `anchor` | `#6F765B` | 鼠尾草灰绿，主状态与选中态 |
| `warm-accent` | `#A66F52` | 陶土暖色，仅作小面积强调 |

#### 怀念模式

| 角色 | 建议值 | 用途 |
| --- | --- | --- |
| `page-bg` | `#F1F2F4` | 月白底色 |
| `surface` | `#F8F7F5` | 主要内容面 |
| `surface-muted` | `#E5E6EC` | 雾灰分区 |
| `text-primary` | `#2C2D33` | 标题与正文 |
| `text-secondary` | `#6B6C76` | 副文案 |
| `rule` | `rgba(44, 45, 51, 0.12)` | 分隔线与边界 |
| `anchor` | `#686E84` | 低饱和蓝灰 |
| `warm-accent` | `#A47D61` | 少量烛光暖色 |

执行规则：

- 一个页面最多出现一个锚点色和一个小面积暖色；
- 不使用纯黑和纯白；
- 不使用三色渐变；
- 不用透明度替代完整的语义色定义；
- 不用大面积高饱和按钮或背景；
- 怀念模式保留暖色，不做黑白丧葬感。

### D.2 字体层级

跨端优先使用系统字体，不依赖网络字体：

```css
font-family: -apple-system, BlinkMacSystemFont, "PingFang SC",
  "Noto Sans CJK SC", sans-serif;
```

可执行层级：

| 层级 | 建议字号 | 使用位置 |
| --- | --- | --- |
| Display | `44-52rpx` | 宠物名、生成结果主标题，单屏最多一个 |
| Page title | `36-40rpx` | 页面标题 |
| Section title | `30-34rpx` | 内容分区标题 |
| Card title | `26-30rpx` | 卡片或列表主信息 |
| Body | `26-28rpx` | 正文和消息 |
| Caption | `22-24rpx` | 副文案、日期、状态 |
| Micro | `18-20rpx` | 极少量辅助信息 |

规则：

- 字重最多使用 Regular、Medium、Semibold 三档；
- 宠物名可使用更有情绪的字形，但必须先验证 Android 字体回退；
- 不在中文界面大量使用全大写英文；
- 不用负字距，所有 letter spacing 保持 `0`；
- 标题靠字号、字重和留白分层，不靠渐变文字。

### D.3 卡片体系

归爪不应让每个模块都成为独立卡片。

#### Level 0：无框内容区

适用于首页宠物主体、页面标题、聊天消息流。通过留白和背景建立区域，不加边框。

#### Level 1：分组面

适用于 today panel、档案摘要、日历主体、设置列表。使用轻背景、细边界和 `16rpx` 左右圆角。

#### Level 2：浮层

只用于弹窗、底部 sheet、关键确认和临时操作面。允许更明确阴影，普通页面不使用这一层级。

#### 胶囊

只用于状态、模式、筛选和单一短动作。不得把长文案或多个操作塞入胶囊。

卡片规则：

- 禁止卡片嵌套卡片；
- 同屏高视觉权重卡片最多一个；
- 普通列表优先使用分隔线；
- 阴影只表达层级，不作发光装饰；
- 玻璃效果只用于导航、浮层或轻工具条，不覆盖所有内容。

### D.4 间距系统

采用 `8rpx` 基础网格：

`8 / 16 / 24 / 32 / 48 / 64rpx`

建议：

- 页面水平 gutter：`32rpx`；
- 顶部安全区后首内容距离：`24-32rpx`；
- 关联元素间距：`8-16rpx`；
- 卡片内部间距：`24-32rpx`；
- 普通区块间距：`40-48rpx`；
- 主焦点与下一内容区：`48-64rpx`；
- 底部内容必须包含 tabBar 与 safe area 余量。

不要给每个 section 相同的上下 padding。宠物主视觉周围应更松，设置列表和快捷项应更紧。

### D.5 顶部区域

顶部只承担三个职责：

1. 当前页面或宠物身份；
2. 当前关系模式；
3. 最多两个必要动作。

规则：

- 标题、副标题和模式状态在同一视觉轴；
- 使用正常文档流，不用负 margin 压叠；
- 右侧圆按钮只放高频命令；
- 页面标题不是营销 Hero；
- chat 等沉浸页面可缩短顶部高度，让内容更快进入视野。

### D.6 底部导航

本次不实现 custom tabbar，但后续应遵循：

- 固定总体高度与 safe area；
- 图标和文字位置不因选中状态跳动；
- 当前项可使用浅填充或细底座，不做夸张放大；
- 只让导航外壳使用轻微半透明；
- 单一图标系统，不混用 emoji、字符和多套线性图标；
- 页面切换使用一次短淡入，不叠加滑动、缩放和弹跳。

### D.7 空状态

空状态固定包含：

1. 当前发生了什么；
2. 为什么这里是空的；
3. 一个明确下一步。

例如：

```text
今天还没有记录
留下一点饮食、精神或陪伴的小事。
[记下今天]
```

规则：

- 不用大空卡；
- 不用仅有插图没有行动；
- 不用“暂无数据”；
- 怀念模式不使用复活暗示；
- 空状态插图不能比真实宠物更抢眼。

### D.8 弹窗

- 简单选择使用底部 sheet；
- 删除、切换怀念模式等重要确认使用居中弹窗；
- 标题直接说明动作；
- 正文说明影响，不制造焦虑；
- 主按钮和取消按钮清楚区分；
- 不在弹窗内嵌第二张卡；
- 打开/关闭建议 `250-300ms`；
- 尊重系统减少动态效果设置。

### D.9 动效

统一节奏：

| 行为 | 时长 | 建议 |
| --- | --- | --- |
| 按压反馈 | `80-120ms` | `scale(0.98)` 或轻微透明度变化 |
| Hover/focus/颜色 | `150-200ms` | 仅属性过渡 |
| 弹窗与 sheet | `250-300ms` | 淡入加少量位移 |
| 页面首次进入 | `400-480ms` | 单次 fade-rise |

规则：

- 每页最多三个主要动效原语；
- 页面只做一次编排式进入；
- 不让所有卡片逐个 fade-up；
- 不做无限动态渐变背景；
- 不做漂浮光球、星点粒子和装饰性扫描线；
- 宠物 idle 动效只在真实电子形象具备合适素材时加入；
- 所有关键操作不依赖 hover；
- 提供 reduced-motion 降级。

## E. 映射到归爪现有页面

### E.1 首页 `home`

#### 当前风险

- 宠物舞台、today panel、动作卡和信息卡容易形成多个竞争焦点；
- 玻璃、渐变和光晕叠加后仍可能像通用 AI 页面；
- 三个等权动作卡会削弱宠物主角；
- 多层卡片使首页重新变成功能面板。

#### 目标宏观结构：宠物肖像 + 今日关系带

1. 顶部：模式、宠物名、一个轻问候；
2. 主体：无框或极弱边界的宠物主视觉；
3. 一句陪伴关系文案；
4. 今日关系带：日期、记录状态、一个主动作；
5. 两个轻量次动作；
6. 最多一条近期信息。

#### 可执行调整

- 电子宠物成为唯一大面积视觉对象；
- 没有 ready 形象时使用克制占位，不显示原始照片；
- 将“记录今天”设为唯一主 CTA；
- “和他/她聊聊”“查看档案”使用轻按钮或列表行，不做三张等权卡；
- week strip 若保留，应嵌入 today panel，且视觉权重低于日期和状态；
- 删除重复的“今天还没有记录”和重复模式说明；
- 背景保持静态低对比层次，不使用持续流动光斑。

### E.2 聊天 `chat`

#### 当前风险

- 标题、上下文模块、快捷问题、服务说明和输入区可能同时争夺空间；
- 多个框体让聊天像 AI 工具壳；
- 怀念模式若保留分析来源或工具标签，会破坏第一人称关系感。

#### 目标宏观结构：关系身份 + 对话流

1. 紧凑顶部身份；
2. 消息流；
3. 初始快捷话题；
4. 固定输入区。

#### 可执行调整

- 宠物头像和名字是顶部核心，阶段说明只保留一行；
- current 的参考信息收进一个可展开区域，不常驻多卡；
- memorial 删除工具型标签，把快捷项写成主人会说的话；
- AI 和用户气泡使用不同表面，不依赖高饱和色；
- 快捷问题使用可换行轻 chip，首条消息后降低存在感；
- 输入栏可使用轻玻璃表面，但页面其他区域减少玻璃；
- 错误状态内联到消息流，不弹出技术错误面板；
- 保持现有 API、Prompt 和历史逻辑不变。

### E.3 我的 `profile`

#### 当前风险

- 统计、账户、会员、宠物切换、设置同时卡片化，容易像后台；
- Plan、inactive、游客状态等开发语义破坏产品气质；
- 宠物关系被账户信息压低。

#### 目标宏观结构：我的归爪空间

1. 当前人与宠物关系摘要；
2. 宠物切换；
3. 账户与备份状态；
4. 分组设置列表。

#### 可执行调整

- 顶部优先展示当前宠物与称呼关系，不展示大面积统计；
- 多宠切换使用稳定横向条或列表，不为每只宠物叠复杂信息；
- “当前为本地体验 / 登录后可开启云端备份”替代技术状态；
- 会员权益缩成一条清晰入口，不展示原始 Plan 字段；
- 设置项使用分组面 + hairline row，不为每项建立卡片；
- 图标使用统一线性图标和浅色底座；
- 留言信箱归入帮助分组，不混入会员区域。

### E.4 日历 `calendar`

#### 当前风险

- 月历、日期格、记录类型、情绪、输入框和保存区层层成卡；
- 日期格若只靠颜色区分，识别与无障碍不足；
- 表单感可能压过“陪伴记录”。

#### 目标宏观结构：日历纸页 + 当日记录抽屉

1. 月份与宠物身份；
2. 单一月历面；
3. 选中日期摘要；
4. 记录编辑区；
5. 明确保存动作。

#### 可执行调整

- 月历作为一个完整 sheet，不给每周或每格额外容器；
- 日期数字使用 tabular number；
- 今天、选中、有记录分别用边界、填充、小点三种信号；
- 记录类型 chip 保持统一高度与选中状态；
- note 区用一张“记录纸”表面，不再嵌套卡；
- 保存按钮在编辑区末端稳定出现；
- current 与 memorial 只切换文案、类型和色温，不改变结构；
- 空状态给一个具体记录建议。

### E.5 欢迎 `welcome`

#### 当前风险

- 品牌、姓名、照片、数字形象和开始按钮若同时成为面板，会增加首次进入压力；
- 多个边框区域让创建流程像填表；
- 形象生成说明可能提前暴露复杂度。

#### 目标宏观结构：一次只完成一个决定

1. 简短品牌与关系承诺；
2. 宠物名字；
3. 一张照片；
4. 继续。

#### 可执行调整

- 首屏只让名字和单张照片入口成为主要任务；
- 阶段默认 current，不做多模式并列展示；
- 使用进度文案而非大型 stepper；
- 照片区域是一项明确行动，不同时显示多个生成状态面板；
- “先上传一张照片就够了”作为安心说明；
- 次要跳过入口弱化但可达；
- 主按钮在内容完成后明显激活；
- 不增加营销插图或多段功能介绍。

### E.6 形象生成 `avatar-generate`

#### 当前风险

- 星空、粒子、扫描线、轨道和深色背景容易变成通用 AI 生成工具；
- 动效元素过多会抢走宠物；
- 原始照片与生成结果可能像两个技术预览框。

#### 目标宏观结构：一束光中的肖像生成

1. 简短阶段文案；
2. 单一肖像主体；
3. 一条可理解的生成进度；
4. 结果与确认动作。

#### 可执行调整

- 删除星点粒子和多重轨道，保留一个光源或柔和轮廓；
- current 使用暖石墨与象牙光，memorial 使用月蓝灰与微暖光；
- 进度用文本阶段 + 细线表达，不伪造复杂 AI 参数；
- 结果图成为唯一焦点；
- “满意，进入首页”是主动作，“重新选择”是次动作；
- 不使用原图填满深色卡片；
- 动效只保留主体显现、进度过渡、结果进入三类。

## F. 不要学什么

1. 不照搬 Hallmark 的具体 HTML、CSS、主题命名或页面截图。
2. 不把网站级超大标题 Hero 直接搬到手机首屏。
3. 不用深黑、网格、星空、粒子制造通用 AI 科技感。
4. 不使用卡片嵌套卡片。
5. 不让所有表面都半透明或 backdrop blur，避免廉价玻璃感。
6. 不使用浮动光球、Aurora blob 和三色渐变作为背景装饰。
7. 不采用三张等宽图标卡作为所有页面的默认功能布局。
8. 不大量使用等宽英文标签、全大写栏目名或后台字段。
9. 不把展示 serif 字体用于所有正文或表单。
10. 不为每个 section、卡片和按钮都添加进入动画。
11. 不使用无限背景呼吸、无目的漂浮和夸张弹跳。
12. 不展示虚构健康分、虚构统计或无实际数据来源的指标。
13. 不制作假系统窗口、假浏览器框或装饰性设备边框。
14. 不照搬网页浮动导航作为 App 底部导航。
15. 不依赖网络字体和外部图片维持基础视觉。
16. 不让怀念模式变成黑白、阴冷或“宠物复活”的灵异空间。

## G. 最小改造优先级

### P0：统一 token 与删减规则

**ROI：最高，风险：低**

- 确认两套语义颜色；
- 确认字体层级和间距网格；
- 统一分隔线、按钮、chip 和浮层；
- 建立“同屏一个高权重表面、禁止卡片嵌套”检查项。

验收：六个页面不再各自使用一套近似但不一致的颜色、圆角和阴影。

### P1：首页焦点重排

**ROI：最高，风险：中**

- 宠物成为唯一主角；
- today panel 合并重复状态；
- 一个主动作加两个轻动作；
- 删除多余卡片与装饰动效。

验收：三秒内能识别宠物、当前关系、今天可以做什么。

### P2：我的页去后台化

**ROI：高，风险：低**

- 弱化统计和开发字段；
- 宠物切换与关系摘要前置；
- 设置项改为分组行；
- 会员、备份、留言信箱回到各自清晰分组。

验收：页面首先表达“我的归爪空间”，其次才是账户与设置。

### P3：聊天页对话优先

**ROI：高，风险：中**

- 收起 current 的参考信息；
- memorial 去工具标签；
- 统一气泡、头像、快捷问题和输入区；
- 不修改 API、Prompt 或聊天历史。

验收：打开页面先看到关系身份和对话，不先看到工具说明。

### P4：日历页合并表面

**ROI：中高，风险：中**

- 月历成为单一 sheet；
- 日期状态更清楚；
- 记录编辑区减少嵌套；
- 保存动作稳定。

验收：用户能快速理解“哪天、有没有记录、现在记什么”。

### P5：欢迎页降低首次成本

**ROI：中，风险：低**

- 单任务推进；
- 一张照片原则；
- 减少面板数量；
- 默认陪伴模式。

验收：首次用户无需理解完整产品结构即可完成创建。

### P6：形象生成页去通用 AI 化

**ROI：中，风险：低**

- 从星空粒子改为单一肖像生成仪式；
- 减少动效种类；
- 结果优先；
- 保持 mock 流程。

验收：页面看起来属于归爪，而不是通用图片生成器。

### P7：单独设计 custom tabbar

**ROI：中，风险：中**

应在六个页面结构稳定后再做。先确定导航项、图标系统、固定高度、safe area 和切换反馈，避免导航改造掩盖页面本身的层级问题。

## 实施检查清单

每轮页面改造完成前检查：

- 是否只有一个视觉主角；
- 是否出现卡片嵌套；
- 是否可以用分隔线替代一张卡；
- 是否出现非必要英文标签；
- 是否存在重复状态或重复入口；
- 陪伴与怀念是否只切换语义和色温，而没有割裂布局；
- 动效是否超过三种；
- 是否尊重 safe area 和 reduced motion；
- 宠物是否仍比工具、统计和装饰更醒目；
- 页面在没有数据时是否给出一个明确下一步。
