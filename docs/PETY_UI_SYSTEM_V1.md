# 归爪 Lumière Pet UI System V1

> 用途：为归爪后续页面改造提供统一、可执行的视觉规范。  
> 适用端：uni-app App（Android / iOS）优先，兼顾 H5。  
> 模式：`current` 陪伴模式、`memorial` 怀念模式。  
> 原则：不靠重型 Web 特效建立高级感，依靠秩序、比例、材质和内容建立长期耐看的体验。

## 0. 产品视觉命题

归爪不是宠物医疗工具、任务管理器或通用 AI 聊天壳。它是一处长期保存宠物关系、日常陪伴和真实回忆的私人空间。

统一视觉命题：

> 宠物是主角，关系是内容，功能退后一步。

所有页面必须回答三个问题：

1. 用户此刻在看谁；
2. 用户与他/她处于怎样的关系状态；
3. 用户现在最自然的下一步是什么。

双模式共用同一套页面骨架：

- `current`：有生活感、清醒、温暖，强调今天与持续陪伴；
- `memorial`：安静、柔和、克制，强调想念与真实拥有过的关系；
- 模式切换只改变色温、文案和少量节奏，不重新发明一套 App；
- 怀念模式不使用黑白丧葬视觉，也不通过 UI 制造宠物复活感。

## A. 品牌气质关键词

归爪的视觉与交互必须同时满足以下 15 个关键词：

1. 温柔；
2. 克制；
3. 私密；
4. 清醒；
5. 安静；
6. 有呼吸感；
7. 有生活温度；
8. 可信赖；
9. 细腻；
10. 长期耐看；
11. 轻而稳定；
12. 不幼稚；
13. 不冷漠；
14. 关系优先；
15. 宠物中心。

检验方式：

- “高级”不能来自更重的阴影、更多渐变或更多动画；
- “温柔”不能等于粉色、卡通插画或过度煽情；
- “苹果感”主要来自清晰层级、稳定几何、系统字体、触控反馈和细节一致性；
- “有呼吸感”主要来自留白、信息密度和节奏，而不是持续漂浮。

## B. 不该出现的视觉问题

以下问题视为 UI 验收失败：

1. 宠物主视觉被统计、健康分、会员卡或功能按钮抢走；
2. 首页直接把带黑底或杂乱背景的用户原图作为 Hero；
3. 同一屏出现三张以上高权重卡片；
4. 卡片内部继续嵌套卡片；
5. 所有模块都使用半透明玻璃，导致边界模糊；
6. 依赖 `backdrop-filter` 才能看清层级；
7. 大面积纯白硬卡浮在奶白背景上；
8. 使用高饱和粉色、紫色或蓝紫渐变制造“高级感”；
9. 使用浮动光球、星空粒子、扫描线或持续动态渐变作通用装饰；
10. 使用 CARE、MODE、PLAN、SMART GUIDE 等后台式英文标签；
11. 页面标题、副标题、状态和按钮彼此争抢视觉权重；
12. 顶部安全区不足，标题被状态栏或胶囊区域挤压；
13. 使用负 margin 或大量 absolute 修补正常内容布局；
14. 三个等权功能卡成为所有页面的固定模板；
15. 空状态只显示“暂无数据”或一张大空卡；
16. 按钮文字过长、自动挤压、换行后改变整体高度；
17. 图标混用 emoji、字符图标和多套线性图标；
18. 仅靠颜色区分选中、今日、异常或禁用状态；
19. 每张卡片都做 fade-up、漂浮或发光；
20. 点击后没有反馈，或使用夸张弹跳反馈；
21. 怀念模式变成全黑、全灰或阴冷灵异空间；
22. 怀念模式出现“复活”“回来陪你”等未经用户明确选择的视觉暗示；
23. 我的页直接展示 `free · inactive` 等开发或后台字段；
24. 聊天页先展示分析来源、工具说明，再展示对话；
25. 日历页像办公排期工具或医疗录入表；
26. 不同页面自行定义相近但不相同的棕色、灰色、圆角和阴影；
27. 内容被 tabBar 遮挡，或底部留白在不同机型上忽大忽小；
28. Android 与 iOS 因字体回退、阴影或模糊差异呈现两套质感。

## C. 配色系统

### C.1 使用规则

- 所有页面使用语义角色，不直接按页面命名颜色；
- 同屏最多一个主色和一个小面积强调色；
- 主按钮、选中态和链接统一使用 `primary`；
- `accent` 只用于日期点、微提示、关系细节等小面积内容；
- 文字对比度以户外手机场景可读为准，不能为了柔和降低到难以辨认；
- 大面积背景不用纯白 `#FFFFFF` 或纯黑 `#000000`；
- 渐变只允许用于大背景或宠物主视觉的极弱纵深，不用于文字和普通按钮；
- 半透明表面必须提供不依赖模糊效果的实色 fallback。

- 不叠加多层彩色 radial gradient；
- 宠物主视觉周围允许一层不动画的暖灰绿柔光。

- 不使用墓碑、羽毛、蜡烛、星空等直白符号反复装饰；
- 暖色只作细微关系温度，不制造宗教或灵异联想；
- current 与 memorial 保持相同功能色语义。

### C.4 透明度与阴影

透明表面推荐：

```text
current: rgba(250, 248, 243, 0.88)
memorial: rgba(248, 247, 245, 0.88)
```

Android 基础阴影：

```text
0 8rpx 24rpx rgba(41, 40, 34, 0.08)
```

iOS 可增强但不得成为结构依赖：

```text
0 12rpx 32rpx rgba(41, 40, 34, 0.09)
```

规则：

- 普通信息卡只使用边框或极轻阴影，两者不同时加重；
- 模态与浮层才使用明确阴影；
- H5/iOS 可渐进增强 `backdrop-filter`；
- Android 无 blur 时，半透明底色仍必须保证完整可读。

## D. 字体与排版层级

### D.1 字体策略

不加载网络字体，优先使用系统字体：

```text
-apple-system
BlinkMacSystemFont
PingFang SC
Noto Sans CJK SC
Microsoft YaHei
sans-serif
```

宠物名或怀念模式短标题可在确认 Android 字体回退稳定后，小范围使用系统宋体作为情绪字体；V1 默认仍使用系统无衬线字体。

### D.2 层级规格

| 层级 | 字号 | 行高 | 字重 | 使用位置 |
| --- | --- | --- | --- | --- |
| 页面标题 | `40rpx` | `56rpx` | 600 | 我的、日历等页面主标题 |
| 宠物主标题 | `48rpx` | `64rpx` | 600 | 首页宠物名，单屏仅一个 |
| 分区标题 | `32rpx` | `44rpx` | 600 | 今日陪伴、宠物档案 |
| 卡片标题 | `28rpx` | `40rpx` | 500/600 | 记录摘要、设置项主标题 |
| 正文 | `28rpx` | `44rpx` | 400 | 聊天气泡、说明正文 |
| 紧凑正文 | `26rpx` | `38rpx` | 400 | 日历、列表与输入内容 |
| 说明文字 | `24rpx` | `36rpx` | 400 | 副标题、辅助说明 |
| 标签/状态 | `22rpx` | `30rpx` | 500 | 陪伴中、今天、已记录 |
| 极小辅助 | `20rpx` | `28rpx` | 400/500 | 字数、版本、时间 |

### D.3 排版规则

- letter spacing 固定为 `0`，不使用负字距；
- 中文标题不使用全大写英文前缀；
- 主标题最多两行，卡片标题优先一行；
- 正文单行建议不超过移动端可读宽度的 90%；
- 数字日期使用 tabular number（平台支持时渐进增强）；
- 说明文字不得低于 `20rpx`；
- disabled 文本仍需可辨认，不用极低透明度；
- 宠物称呼保持产品语气一致，current 可按用户设置使用他/她，memorial 优先使用已配置称呼；
- 不用渐变字、描边字和发光字。

## E. 间距系统

### E.1 基础单位

归爪采用 `8rpx` 基础网格，约等于设计稿中的 4px 步进，适合 uni-app 的 750rpx 设计宽度。

| Token | 数值 | 用途 |
| --- | --- | --- |
| `space-1` | `8rpx` | 图标与短文字 |
| `space-2` | `16rpx` | 紧密关联元素 |
| `space-3` | `24rpx` | 列表行与小组件内部 |
| `space-4` | `32rpx` | 页面 gutter、普通卡片内部 |
| `space-5` | `40rpx` | 关联区块 |
| `space-6` | `48rpx` | 普通 section |
| `space-8` | `64rpx` | 主视觉与下一任务 |
| `space-10` | `80rpx` | 极少量大段落间隔 |

### E.2 页面规则

- 页面水平 gutter：`32rpx`；
- 小屏最低 gutter：`24rpx`，不得再缩小；
- 顶部内容从系统安全区后开始；
- 顶部标题区底部间距：`32-40rpx`；
- 主焦点周围：`48-64rpx`；
- 表单字段垂直间距：`24-32rpx`；
- 设置行最小高度：`96rpx`；
- 按钮之间最小间距：`16rpx`；
- 页面底部保留 tabBar 高度、设备 safe area 和额外 `24rpx`；
- 不使用负 margin 修复模块关系；
- absolute 仅用于非交互装饰、角标和明确浮层。

### E.3 跨端尺寸

- 以 375-390px 逻辑宽度为主要验收视口；
- 同时检查 360px Android 小屏；
- 所有触控目标最小约 44px，即 uni-app 设计中不低于 `88rpx`；
- 不按 viewport width 缩放字体；
- 长宠物名必须有截断或两行上限，不能挤压右侧按钮；
- 键盘弹出后输入区不得被遮挡。

## F. 卡片系统

普通圆角控制在 `16rpx`（约 8px）以内。只有模态、宠物主视觉大容器等已有特殊结构可使用 `20-24rpx`，且不能成为全局默认。

### F.1 主卡

用途：

- 首页今日陪伴；
- 当前宠物摘要；
- 日历主体。

规格：

- 一屏最多一张；
- 背景 `surface`；
- 圆角 `16rpx`；
- 内边距 `32rpx`；
- 边框 `1rpx solid rule`；
- 可使用轻阴影；
- 必须包含一个明确主信息和最多一个主动作。

### F.2 次卡

用途：

- 最近记录；
- 云端备份状态；
- 怀念模式状态。

规格：

- 背景 `surface-muted` 或轻透明 `surface`；
- 圆角 `16rpx`；
- 内边距 `24rpx`；
- 默认无阴影；
- 信息量不超过标题、说明、一个尾部动作。

### F.3 信息卡

用途：

- 一条照护提醒；
- 一条回忆摘要；
- 错误或成功提示。

规格：

- 优先做成带左侧图标的横向信息行；
- 高度随内容，但最小 `88rpx`；
- 可用 `rule` 分隔而非独立背景；
- 不出现复杂插图；
- 错误提示文案温和，但必须明确下一步。

### F.4 功能卡

用途：

- 低频入口；
- 我的页功能分组。

规格：

- 多个功能优先组成一张分组面；
- 每一项使用统一图标、标题、可选说明和箭头；
- 行间使用 hairline；
- 不为每个入口建立浮动卡片；
- 高频主动作不使用功能卡表达，应使用按钮。

### F.5 空状态卡

固定结构：

1. 小型占位图形或真实宠物相关视觉；
2. 一句状态标题；
3. 一句具体说明；
4. 一个下一步动作。

规格：

- 不使用大面积纯白容器；
- 不写“暂无数据”；
- 不使用与宠物无关的通用插图；
- 插图不得比宠物主视觉更大；
- memorial 文案不制造复活感或负罪感。

### F.6 浮层 / 弹窗

用途：

- 删除确认；
- 切换怀念模式；
- 照片来源选择；
- 宠物切换；
- 关键错误恢复。

规格：

- 简单选择优先底部 sheet；
- 高风险确认使用居中弹窗；
- 弹窗圆角可用 `24rpx`；
- 内容边距 `32rpx`；
- 标题、影响说明、主次按钮顺序固定；
- 不在弹窗内嵌卡；
- 不连续弹出两个确认层；
- 遮罩使用低透明暖灰或蓝灰，不使用纯黑。

## G. 按钮系统

### G.1 主按钮

用途：每个任务区唯一的确认或推进动作。

规格：

- 高度 `88-96rpx`；
- 圆角 `16rpx`；
- 水平内边距不少于 `32rpx`；
- current 使用 `surface-strong` 或 `primary`；
- memorial 使用对应 `surface-strong` 或 `primary`；
- 文字 `26-28rpx / 600`；
- 一屏避免同时出现两个同权主按钮。

### G.2 次按钮

用途：重新选择、稍后处理、次级入口。

规格：

- 高度与同组主按钮一致；
- 浅表面 + `rule` 边框；
- 文字使用 `text`；
- 不通过更小触控区域表达次级。

### G.3 轻按钮

用途：查看全部、继续生成、编辑、切换。

规格：

- 最小触控高度 `72-80rpx`，外围点击区补足至 44px；
- 可以是文字加箭头或小胶囊；
- 不使用大阴影；
- 不在同一区域连续排列三个以上。

### G.4 图标按钮

用途：返回、更多、关闭、添加、发送。

规格：

- 可见尺寸 `72-80rpx`；
- 实际触控区不低于 `88rpx`；
- 使用项目统一图标库；
- 熟悉命令优先使用图标，陌生命令提供 tooltip 或文字说明；
- 不使用“归”字、emoji 或文字符号冒充通用图标；
- 圆形按钮只用于单一明确动作。

### G.5 禁用状态

- 保留原按钮几何尺寸；
- 背景使用 `surface-muted`；
- 文字使用 `text-tertiary`；
- 禁止点击、禁止震动；
- 表单应同时说明不能提交的具体原因；
- 不只通过 opacity 表示禁用。

### G.6 点击反馈

- 按下时长 `80-120ms`；
- 普通按钮 `scale(0.98)`；
- 图标按钮 `scale(0.96)`；
- 大面积功能卡最多 `scale(0.99)`；
- 可使用 `uni.vibrateShort`，失败静默；
- 跳转不得等待震动完成；
- 不使用弹簧过冲、夸张阴影或连续波纹。

## H. 页面级结构模板

### H.1 首页

目标：打开后三秒内看到宠物、关系状态和今天可以做什么。

固定顺序：

1. 顶部身份区：模式、宠物名、最多两个图标动作；
2. 宠物主视觉区：只展示 ready 的电子形象或克制占位；
3. 陪伴关系句：一到两行；
4. 今日陪伴主卡：日期、今日状态、一个记录主动作；
5. 两个次级动作：聊天、档案；
6. 最多一条近期记录或照护提醒。

Current：

- 主句围绕“今天”“陪伴天数”“刚刚发生的小事”；
- 主动作是“记录今天”；
- 强调色可用于今日状态和记录点。

Memorial：

- 主句围绕“今天想起他/她”“真实拥有过的回忆”；
- 主动作是“写一段回忆”；
- 不出现健康分、连续打卡压力或复活暗示。

禁止：

- 三张等权动作卡；
- 原始照片直接作为 Hero；
- 重复 today panel；
- 首页承担复杂生成流程；
- 大面积空卡和多层动态背景。

### H.2 聊天

目标：让关系身份和对话先于 AI 工具说明。

固定顺序：

1. 紧凑顶部：宠物头像、名字、模式副标题；
2. 可滚动消息流；
3. 初次进入时的轻量快捷话题；
4. 键盘安全的固定输入区。

Current：

- 角色为宠物陪伴与照护助手；
- 必要参考信息收进一个可展开区域；
- 高风险提示清晰，但不把所有回复视觉都做成警告。

Memorial：

- 顶部和 AI 消息使用宠物头像；
- 快捷项写成主人会说的话；
- 不显示“本次会参考”“基础档案”“最近日历”等工具说明；
- 页面气质更安静，但文字对比度不降低；
- 不通过头像光环、星光或文案暗示真实复活。

消息规则：

- 用户消息与对方消息只用两种表面；
- 连续同方消息减少重复头像；
- 时间信息按需显示；
- 错误状态以内联消息呈现；
- 长消息保持舒适行高，不做满宽气泡。

### H.3 我的

目标：呈现“我的归爪空间”，而不是账户后台。

固定顺序：

1. 当前关系摘要；
2. 宠物切换；
3. 账户与备份状态；
4. 设置与帮助分组；
5. 会员入口作为独立但克制的业务项。

规则：

- 当前宠物优先于用户等级；
- “当前为本地体验”“登录后可开启云端备份”替代技术字段；
- 多宠物使用稳定横向切换或列表；
- 设置项使用分组行，不使用卡片瀑布；
- 留言信箱放在帮助分组；
- 退出、删除等危险动作与普通设置分离；
- memorial 模式只改变当前宠物摘要的语气与色温，不改变账户功能。

### H.4 日历

目标：像陪伴记录纸页，而不是排期工具或医疗表单。

固定顺序：

1. 月份与当前宠物；
2. 单一月历 sheet；
3. 选中日期摘要；
4. 记录类型与内容编辑；
5. 稳定保存动作。

Current：

- 类型围绕饮食、精神、体重、疫苗、驱虫和异常观察；
- 医疗相关内容保持清晰，不使用红色制造常态焦虑。

Memorial：

- 类型切换为回忆、照片、给他/她的话、纪念日和共同故事；
- 月历布局不变；
- 不使用连续打卡压力文案。

日期状态：

- 今天：细描边；
- 选中：主色浅底；
- 有记录：小实点；
- 异常或重要：小面积状态色加图形提示；
- 不只靠颜色区分；
- 日期必须保持 7 列稳定横排。

## I. 动效规范

### I.1 页面进入

- 时长 `360-440ms`；
- 使用 opacity + `8-12rpx` 向上位移；
- 每页只在首次进入时执行一次；
- 页面内所有卡片不再分别重复入场；
- Android 低端设备可只保留淡入。

### I.2 卡片出现

- 仅动态新增内容使用；
- 时长 `220-280ms`；
- 使用淡入或极小高度过渡；
- 不做通用 stagger；
- 列表加载不逐项弹跳。

### I.3 点击

- `80-120ms`；
- 按钮、图标和卡片使用 G.6 的统一缩放；
- 颜色变化与缩放使用同一 timing；
- 点击反馈不能造成布局变化。

### I.4 页面切换

- 优先使用 uni-app / 原生导航默认转场；
- 不叠加自定义全屏滑动；
- tab 页面使用短淡入即可；
- current 与 memorial 切换使用 `200-280ms` 颜色过渡；
- 不动画大面积背景位置。

### I.5 弹窗

- 遮罩淡入 `180-220ms`；
- 弹窗或 sheet 进入 `250-300ms`；
- 位移不超过 `24rpx`；
- 关闭略快于打开；
- 不使用弹簧和旋转。

### I.6 底部导航切换

- 总高度、图标位置和文字基线保持固定；
- 当前项填充与颜色过渡 `160-200ms`；
- 图标最多轻微缩放至 `1.04`；
- 不使用移动光块跨越多个 tab；
- 跳转反馈不依赖毛玻璃。

### I.7 跨端降级

- 不依赖 CSS filter、mix-blend-mode、复杂 mask 和 WebGL；
- `backdrop-filter` 仅为渐进增强；
- H5 可响应 `prefers-reduced-motion`；
- App 端提供关闭复杂动画后的静态可用状态；
- 低端 Android 首先保证滚动、输入和跳转流畅；
- 所有加载动画必须有超时与文本状态，不能只靠视觉循环。

## J. 组件统一策略

### J.1 顶栏

组成：

- 安全区；
- 返回或页面身份；
- 标题/宠物名；
- 一行副标题或模式；
- 最多两个右侧动作。

统一规则：

- 高度稳定；
- 不用负 margin；
- 长标题不挤压右侧动作；
- 模式标签使用文字或小状态点，不做大胶囊；
- 首页可使用大宠物名，其他页使用标准页面标题。

### J.2 头像

宠物头像优先级：

1. `generatedAvatarUrl`；
2. `generatedAvatar`；
3. `avatar`；
4. 其他已有宠物图片兼容字段；
5. 默认宠物占位。

规则：

- 首页主视觉不直接使用用户原始照片；
- chat memorial 的顶部头像与对方消息头像都使用当前宠物头像；
- 小头像统一圆形，常用尺寸 `64 / 80 / 96rpx`；
- 边框最多 `1rpx`；
- 不用“归”字作为宠物头像；
- 图片加载失败时保持容器尺寸稳定。

### J.3 宠物主视觉区

- 只有首页和形象生成结果页允许大宠物主体；
- 主体使用 `object-fit: contain`；
- 不裁切头部、耳朵和脚部；
- 不直接展示黑底矩形原图；
- 没有生成图时使用轻量轮廓和状态说明；
- 占位不模拟一只过度具体的宠物，避免与真实宠物竞争；
- 不用大白卡、复杂光环或持续漂浮作为默认；
- 未来真实生成图接入后再评估轻量 idle 动效。

### J.4 底部导航

- 本 V1 不强制 custom tabbar；
- 先统一页面底部安全区；
- 后续导航最多 5 项；
- 使用同一线性图标系统；
- 当前项使用主色与浅底；
- 不用浮动球形主按钮；
- memorial 只换颜色，不换导航结构；
- 导航容器可轻透明，但无 blur 时仍完整。

### J.5 输入框

- 默认高度不低于 `88rpx`；
- 多行输入按内容增长但设置最大高度；
- 背景使用 `surface-muted`；
- 边框使用 `rule`；
- focus 使用 `focus` 色描边，不使用发光；
- placeholder 使用 `text-tertiary`；
- 错误说明放在字段下方；
- chat 输入区必须适配键盘和 safe area；
- 发送按钮保持独立触控区。

### J.6 快捷入口

适用于：

- chat 快捷话题；
- calendar 记录类型；
- home 今日快速记录。

规则：

- 使用 chip、分组行或轻按钮，不使用卡片墙；
- 高度统一；
- 文案优先 2-8 个中文字符；
- 允许换行，但同一行不挤压；
- 选中态使用浅底 + 文字/图标双重变化；
- current 与 memorial 使用不同文案，不只换颜色；
- 每组最多 4-6 个首屏选项，更多内容进入对应页面；
- 点击只触发现有业务，不在首页复制复杂流程。

## 附录：逐页 UI 验收清单

每次改造页面时逐项确认：

- 是否有且只有一个高视觉权重焦点；
- 宠物或关系内容是否先于工具与账户信息；
- 是否出现卡片嵌套；
- 是否可以用分隔线替代一张卡；
- current 与 memorial 是否使用同一布局骨架；
- 两种模式是否同时保持足够文字对比度；
- 是否存在后台式英文标签；
- 是否存在重复状态、重复按钮或重复说明；
- 主动作是否唯一且明确；
- 触控区域是否不低于约 44px；
- 是否适配状态栏、底部 safe area 和键盘；
- Android 无 blur、弱阴影时是否仍然完整；
- 动效是否最多三种且不影响操作；
- 空状态是否提供具体下一步；
- 是否在 360px 与 390px 视口检查长文案；
- 是否没有新增业务逻辑、数据结构或 API 依赖。
