# 归爪 Lumiere Pet 产品决策 V0.1

更新日期：2026-06-15

## 本轮改动说明

本轮只新增产品结构决策文档，不做大规模 UI 改动，不删除业务文件，不修改 `uni_modules`。

原因：当前项目已经有可运行的首页、问诊、我的、档案、日历等闭环，但页面职责和三阶段关系模型仍需要先统一口径；先沉淀决策文档，可以降低下一轮重构误删、误改、跑偏的风险。

## 产品一句话定位

归爪 Lumiere Pet 是一个围绕人与宠物关系全周期的安静陪伴工具：在相遇前帮助用户准备，在陪伴中帮助用户记录与照护，在纪念里帮助用户温柔保存回忆。

## 三个关系阶段

### 相遇前

关系状态：`future`

核心任务：

- 判断自己是否适合开始养宠。
- 梳理预算、时间、居住环境和照护能力。
- 准备接宠清单、初期流程、附近医院备选信息。
- 记录偏好、顾虑和准备进度。

### 陪伴中

关系状态：`current`

核心任务：

- 管理宠物基础档案。
- 记录日常状态、事件、用药、疫苗和异常变化。
- 在问诊前自动汇总档案与近期日历，减少重复描述。
- 对高风险症状先提示线下就医，再允许用户继续整理信息。

### 纪念里

关系状态：`deceased`

核心任务：

- 温柔保存宠物的照片、性格、习惯和重要记忆。
- 支持用户写信、整理回忆、记录纪念日。
- 将问诊式入口转为陪伴式、书信式入口。
- 避免用强功能打扰用户的情绪节奏。

## 三阶段共用功能

- 关系对象管理：名称、照片、当前关系阶段、展示模式。
- 首页：根据关系阶段切换标题、快速入口、统计口径和文案。
- 档案：保存与当前关系对象相关的基础信息、偏好、备注。
- 日历/记录：按日期记录状态、事件和手写内容。
- 对话入口：根据阶段切换为备宠咨询、照护问诊或纪念陪伴。
- 本地数据隔离：按宠物/关系对象 ID 保存档案、日历、对话和摘要。
- 账号与会员占位：保留登录、权益、数量限制和额度说明，但不在本轮扩展支付或真实会员闭环。

## 每阶段专属功能

### 相遇前专属

- 适养评估。
- 接宠准备清单。
- 接宠前后流程规划。
- 医院备选清单。

### 陪伴中专属

- 宠物健康档案。
- 日常状态打卡。
- 报告解读入口。
- 拍照问诊入口，但目前只作为“图片 + 文字补充”的低成本流程，不接真实视觉识别。
- 急症风险提示。
- 就医服务页的本地医院信息占位。

### 纪念里专属

- 写给它的信。
- 回忆整理。
- 纪念日整理。
- 情绪陪伴式对话。

## 暂缓功能清单

- 地图、轨迹、实时定位和地图 POI 自动检索。
- 社交、社区、动态流、关注和评论。
- 商城、购物车、订单和商品推荐。
- 真实 AI 图片生成 API。
- 真实多模态识图、OCR 报告识别和自动影像诊断。
- 支付、订阅和完整会员交易闭环。
- 云端同步的完整数据迁移。
- 多专家团、营养配餐、行为训练等独立大模块。
- 对标或复刻任何竞品页面。

## 首页统一结构建议

首页应保留一个统一骨架，由 `common/relationship-config.js` 按关系阶段提供差异内容。

建议结构：

1. 关系对象舞台
   - 展示名称、照片或 2.5D 模式。
   - 展示当前阶段短文案：准备相遇、正在陪伴、被温柔记得。

2. 今日状态区
   - 相遇前：今天的准备计划。
   - 陪伴中：今天的照护和记录。
   - 纪念里：今天的想念和纪念。

3. 四个快速入口
   - 相遇前：适养、清单、档案、医院。
   - 陪伴中：档案、日记、问诊、就医。
   - 纪念里：写信、回忆、记录、陪伴。

4. 阶段统计卡
   - 相遇前：准备天数、记录片段、咨询次数。
   - 陪伴中：陪伴天数、回忆记录、对话次数。
   - 纪念里：记得天数、回忆记录、信件次数。

5. 档案摘要卡
   - 始终跳转到档案页。
   - 内容根据阶段解释为未来计划、宠物档案或纪念档案。

原因：统一骨架能避免为三个阶段做三套首页，减少维护成本；差异只放在配置和少量条件逻辑里，能让产品气质统一。

## 当前项目结构诊断

### 路由与页面

`pages.json` 当前注册了自研页面：

- `pages/welcome/welcome`：关系对象创建/编辑入口，已承载三阶段选择。
- `pages/home/home`：tab 首页，已读取 `relationship-config` 做阶段化展示。
- `pages/chat/chat`：tab 对话页，已按阶段切换为问诊、备宠、信箱式入口。
- `pages/profile/profile`：tab 我的页，包含宠物列表、登录状态、会员说明和功能菜单。
- `pages/calendar/calendar`：日历记录页。
- `pages/insights/insights`：记录明细页。
- `pages/archive/archive`：档案编辑页。
- `pages/care/care`：就医服务页。
- `pages/auth/login`、`pages/auth/register`：自研登录注册页。

`pages.json` 同时注册了 `uni_modules/uni-id-pages` 下的登录、注册、找回密码、账号信息等页面。

原因：项目当前存在两套认证入口，自研 `pages/auth/*` 与 `uni-id-pages` 并存，后续需要统一入口，避免用户路径和维护成本分裂。

### tabBar

当前 tabBar 为：

- 首页：`pages/home/home`
- 问诊：`pages/chat/chat`
- 我的：`pages/profile/profile`

原因：三 tab 主轴清晰，适合继续保留；`chat` 的 tab 文案已由 `setRelationshipTabBar` 按阶段动态改为问诊、备宠或信箱。

### common 目录

当前 common 模块：

- `relationship-config.js`：三阶段文案、首页入口、聊天入口和 tab 文案配置。
- `pet-store.js`：宠物/关系对象列表、本地 active pet、数量限制和旧缓存兼容。
- `profile-store.js`：档案存储、完成度、档案上下文构造。
- `diary-store.js`：日历记录、心情/事件标签、问诊上下文构造。
- `consultation-store.js`：问诊摘要本地存储。
- `hospital-store.js`：就医页示例医院和急症提示。
- `auth-store.js`、`auth-session.js`、`auth-captcha.js`：账号状态、uniCloud 登录相关能力。

原因：数据层已经具备本地闭环基础，下一轮应优先统一命名和阶段语义，而不是新增大模块。

### components 目录

当前没有自研 `components` 目录。

原因：UI 结构主要写在页面内，短期可运行；但后续若继续扩展首页卡片、顶部栏、宠物头像、空状态等，应逐步抽组件，避免页面继续膨胀。

## 废弃、实验、未注册、硬编码 mock 页面

### 明确未注册页面

- `pages/index/index.vue`

判断：该页不在 `pages.json` 中，包含独立 PIXI 2.5D 实验、健康仪表盘、专家团、营养配餐、小目标等内容，且大量数据写死。

处理建议：暂不删除，先视为实验页。后续可在 `docs/archive` 写入归档说明，或在确认无引用后移动到 `docs/archive/pages-index-experiment.md` 说明其历史用途。

原因：该页包含早期探索信息，但已偏离当前“三阶段关系模型 + 三 tab 主轴”的产品结构，直接保留在 `pages` 下会增加误读成本。

### 硬编码 mock/占位数据页面

- `pages/care/care.vue`
  - 页面明确展示“示例数据/待接入”。
  - 数据来自 `common/hospital-store.js` 的 `demo_*` 医院列表。
  - 刷新位置只提示地图 POI 待接入。

- `pages/index/index.vue`
  - 健康档案、待办、专家团等均为页面内硬编码展示。
  - 不在路由中，应作为实验页归档。

- `pages/profile/profile.vue`
  - 会员权益和云同步仍是说明/占位，不是完整交易和云同步闭环。

- `pages/chat/chat.vue`
  - 已调用 `api_deepseek` 云函数；但图片上传只作为图片消息和文字补充，不是真实视觉识别。

原因：这些内容当前对产品闭环有提示价值，但不能在下一轮被误认为真实服务能力。

### 可能需要重构的页面

- `pages/welcome/welcome.vue`：承担创建、编辑、阶段选择、照片上传，职责偏多；可先不拆，但后续应明确“创建关系对象”和“编辑当前对象”的差异。
- `pages/home/home.vue`：首页逻辑较重，含 PIXI renderjs、统计、档案摘要、快速入口处理；后续适合抽 `relationship-config` 使用层和首页卡片组件。
- `pages/chat/chat.vue`：对话、图片选择、风险识别、云函数调用、咨询摘要保存都在单页内；后续应抽出消息构造和风险规则。
- `pages/profile/profile.vue`：宠物切换、账号、会员、统计和菜单混合；后续应拆分账号/宠物管理/菜单配置。
- `pages/archive/archive.vue`：当前偏“陪伴中健康档案”，对相遇前和纪念里不够贴合；应按阶段调整字段显示。
- `pages/calendar/calendar.vue`：当前事件词表偏健康照护，对相遇前和纪念里需要阶段化词表。
- `pages/insights/insights.vue`：目前依赖 memory/events/chat 三类，可保留，但命名需要与三阶段统计口径统一。

原因：以上页面不是废弃，而是已进入主线但承担了过多职责；应小步重构。

## 建议暂缓功能

- `pages/index/index.vue` 中的专家团、营养配餐、小目标和独立健康仪表盘。
- `pages/care/care.vue` 中的真实地图 POI。
- `pages/chat/chat.vue` 中的真实图片识别和真实报告 OCR。
- `pages/profile/profile.vue` 中的支付会员、完整云同步和商业化闭环。

原因：这些能力会显著扩大成本和产品边界，且与本轮“三阶段关系模型统一”目标无关。
