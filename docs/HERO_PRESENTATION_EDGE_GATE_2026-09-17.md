# Hero 展示层与防粉边

## A. 根因

旧展示只有一个通用椭圆阴影；角色上下移动时阴影不动，脚底缺少接触点。角色宽度偏大，卡片、角色和背景的光影缺少分层。

原边缘检测主要识别饱和洋红，容易漏掉淡粉污染和与主体断开的细胡须。PNG 本身使用 straight alpha，未发现重复预乘代码；本轮固定了 straight-alpha 输出与合成约定，透明像素 RGB 归零，避免后续采样带入技术底色。

## C. 长期机制与阈值

1. 以透明边界建立距离场；检测边缘 1–4 源像素，以内部可靠前景颜色作为参考。已与主体断开的细毛也参与检测。
2. 修复近边缘 8 源像素中的色溢出/灰雾，不改内部粉色鼻子、耳朵和毛色。孤立染色细毛只净化颜色，保留 alpha。
3. 外侧分数 alpha 做 1 源像素柔和收边，不对整个主体反复腐蚀，不在 UI 上模糊高清主图。RGB 不乘 alpha；渲染合成时只乘一次。
4. 叠加白色、App 当前背景 `#F5F2EC`、深灰 `#232628`、对比青色 `#2A778B`。合成后明显色差阈值：色溢出通道误差 >10/255、灰雾 >18/255，同时须满足局部色差特征。
5. 拒收条件任一成立即失败：色溢出比例 >0.5%；灰雾比例 >1%；8 邻域连续色溢出 >12 像素；连续灰雾 >32 像素；无可检测边缘。
6. 最多两轮净化，第二轮仅修颜色，不再缩 alpha；失败抛出 `HERO_EDGE_QUALITY_REJECTED`，不上传替换文件。最终 tight 文件再过一次门槛。保留原成功文件，不新增付费生成重试。

这使处理和拒收随每次真实 Hero 保存执行，而非一次性修图。上述是可复现的像素启发式，不能保证任意未来照片绝无可见缺陷；多背景复核和显式拒收指标用于继续定位，而非把“有 alpha”当作全部质量证明。

最终真实资源：1491×2007，2,505,055 字节；SHA256 `53f1fc600b3eedd28f434b27c31bb8d8063c9d0fc155aec07119f2da8809c979`，file hash `9293e630`。实际检测 19,334 个边缘像素，色溢出 0、灰雾疑似点 9（0.0466%），最大灰雾连片 3，四背景均通过。字节减少主要来自清除完全透明区域残留 RGB，不是把高清角色降低分辨率；边界尺寸变化来自约 1 像素收边。

## D. 展示与姿态

- 卡片柔和表面渐变、细微内高光和两档外阴影。
- 角色主层置于卡片前方，宽度由 66% 改为 64%，向卡片内收一点，保留克制越界。
- 背后环境影与气氛光；脚底和尾巴各有接触影，下方另有宽而淡的环境落影。
- 呼吸不再整体上下漂移，改为以实际 alpha 脚底为锚点的 0.1% 横向 / 0.4% 纵向变化，周期 7 秒。
- 按压角色轻微压缩，阴影同时加深、扩展；放开轻微回弹。触摸位移上限 3px，纵向移动超过 18px 后退出角色视差，保持页面滚动。
- reduce-motion 同时关闭角色动效、视差与阴影过渡，静态图层保留。未引入逐帧 JS 循环或大型动画依赖。
- 姿态规范继续由独立 composition contract 约束 initial/regenerate/revision：完整友好坐姿、轻微 3/4、面向用户，参考照片只提供身份。Hero 技术任务只接收已确认 master 并保留它的姿势，不重新使用原照片姿势，也不向已成功的背景编辑 prompt 塞入互相冲突的重新摆姿指令。未新增付费姿态生成验证，不能声称已覆盖所有异常参考图。
