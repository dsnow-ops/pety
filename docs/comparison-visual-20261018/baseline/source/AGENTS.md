# 归爪开发与测试约定

## 电脑优先，真机阶段性验收（用户指令，2026-10-16）

本约定调整测试频率与交付方式，不更改产品需求、深暖视觉母版、安全边界、会员权益和数据保护规则。后续明确用户指令优先。

- 日常开发、界面、表单、导航和一般回归优先运行当前真实 uni-app 项目的 H5。使用已有 HBuilderX 构建方式及浏览器/Playwright；验证 localhost 实际可达，不以独立 HTML、生成图或编译成功代替实际交互。
- 视觉修改优先检查 360、390、412 逻辑像素宽度，操作点击、输入、滚动并检查日志、截图，发现问题继续修复。不为控制 HBuilderX 内置浏览器投入大量时间，不引入大型测试框架或更换技术栈。
- 原生 API、系统权限、相册/相机/视频、Android 冷启动/页面栈/返回/前后台、真实 Canvas 导出/多指手势、单设备登录/云鉴权，以及重要功能组或最终候选版本，集中列出平台验收清单。
- 连接真机前说明本次具体检查项；合并验收，避免反复连接部署。设备不可用时继续可独立验证的工作，标记“待真机验收”，不得阻塞全部开发。
- 分别记录 H5 实测、自动化测试、Android 模拟器、Android 真机状态。模拟器不等于用户手机，H5 不等于 App；plus API、路径、媒体持久化、系统相册、权限、返回、WebView 和安全区单独判断。
- 不为 H5 通过删原生功能、改变正式逻辑为假成功或破坏已有兼容修复。
- 交付实际修改、可复现入口、本轮真实 H5 截图、交互结果、已知问题及未验证原因；重要原生节点附集中验收清单。
- 本规范不授权生产部署、付费 API、删除真实资料、清除 App 数据或修改会员规则。保护已有未提交改动；不自动 commit/push/reset/clean/stash。

当前可用构建示例：`node scripts/build-dual-mode.cjs h5 <本轮隔离输出目录>`。构建输出目录应按任务区分，历史证据不可充当新结果。具体脚本执行前核查是否有外部请求或破坏性行为。
