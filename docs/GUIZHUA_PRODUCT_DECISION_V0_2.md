# 归爪 Lumière Pet 产品决策 V0.2

更新日期：2026-06-15

## 新定位

归爪 Lumière Pet 是一个默认陪伴型宠物关系档案 App。核心体验围绕正在陪伴的宠物展开：建立档案、记录日常、整理照护线索、在需要时进入对话辅助。

## 结构调整

### current / 正在陪伴

`current` 是默认主体验，也是新用户创建宠物时的默认关系状态。

核心任务：
- 建立宠物档案。
- 记录日常、健康、体重、疫苗、驱虫和异常观察。
- 让首页、记录、档案、聊天围绕同一个陪伴对象工作。
- 在医疗相关问题上保持边界：只做观察和记录建议，不替代兽医诊断。

### deceased / 温柔纪念

`deceased` 是隐藏纪念模式，不再作为首页或新建流程里的并列入口。用户需要在档案中主动开启。

开启后：
- App 主布局不变。
- 首页文案、记录语义、聊天身份和整体氛围切换为纪念模式。
- 不删除任何档案、记录或聊天历史。
- 用户可以恢复为陪伴模式。

纪念聊天边界：
- 不默认假装宠物复活。
- 不说“我回来了”“我一直在你身边”等制造复活感的话。
- 默认只陪用户整理真实回忆、纪念文字和情绪表达。
- 如果未来要做“宠物口吻陪伴”，必须先弹出明确引导，并收集宠物性格、习惯、说话风格、用户接受边界后再开启。

### future / 准备相遇

`future` 暂缓，不作为主入口，也不在新用户创建流程展示。

保留原因：
- 兼容旧数据。
- 保留后续重新评估“准备相遇”场景的可能性。
- 避免物理删除导致旧宠物、旧记录或旧聊天崩溃。

实现原则：
- 配置标记为 `legacy/deprecated`。
- 不在 onboarding 主选项中出现。
- 旧 `future` 宠物仍可打开和读取文案。

## 电子宠物形象

电子宠物形象是后续核心入口之一，承担“宠物关系对象”的视觉锚点。本轮只保留前端字段、mock 流程和服务抽象层，不接真实 AI 图片生成 API，不做真实上传，不做真 3D，不做付费。

未来真实生成 API 应该替换在 `common/pet-avatar-generator.js` 的 job 创建和轮询位置，页面继续只读取统一的显示结果。

## 首页结构建议

首页不做三套并列结构。保留同一套主布局：
1. 宠物形象和当前关系氛围。
2. 今日记录入口。
3. 档案摘要。
4. 对话入口。
5. 数字形象入口。

差异只由 `relationshipStage` 和 `relationship-config.js` 切换文案、语义和主题 class。

## 暂缓清单

- 地图、轨迹、定位、POI。
- 社交、动态、关注、评论。
- 商城、购物车、订单。
- 真实 AI 图片生成 API。
- 真实支付和会员交易闭环。
- 宠物复活式默认聊天。
- 真 3D 模型和复杂形象编辑器。
