# 归爪 Lumière Pet 首页 UI 重构 Brief V0.3

更新日期：2026-06-15

## 1. 首页设计目标

归爪首页不再是功能面板，也不应该像普通工具型宠物 App 那样把入口、指标、提醒和卡片全部堆在首屏。

新的首页定位是：**宠物舞台 / 宠物生命卡首页**。

用户打开 App 的第一眼，应该感觉自己的宠物被温柔、认真、体面地放在这里。首页首先承载情感关系，其次才承载功能入口。

首屏必须稳定呈现四件事：

- 宠物形象：电子宠物形象是视觉主角，不是角落头像。
- 宠物名字：让用户立刻知道这是属于哪只宠物的空间。
- 陪伴状态：正在陪伴或温柔纪念，语气轻，不做强提示。
- 三个核心动作：记录今天 / 和它聊聊 / 查看档案。

首页的目标不是“让用户看到很多功能”，而是让用户愿意停留，并自然知道下一步可以做什么。

## 2. 首页信息架构

首屏建议采用从上到下的轻层级结构：

1. 顶部问候区
   - 宠物名作为第一识别信息。
   - 一句轻量问候，例如“糖蒜今天也在这里”。
   - 右侧保留模式入口或状态入口，例如“陪伴中”或“纪念模式已开启”。
   - 顶部不要放太多工具按钮，避免打散第一眼情绪。

2. 中央 Hero 区
   - 电子宠物形象位于屏幕视觉中心。
   - 形象区域占据首屏最重要的垂直空间。
   - 可使用柔和底座、低透明玻璃层、浅光晕或柔影承托。
   - 不使用普通圆形头像作为主展示。

3. 陪伴语句
   - 放在 Hero 下方或与 Hero 轻微重叠。
   - 示例：“糖蒜今天也在这里，已经陪伴你 126 天。”
   - deceased 模式可变为：“糖蒜被温柔地留在这里，今天也可以慢慢想起它。”
   - 文案应短、克制，不做营销式口号。

4. 三个核心按钮
   - 记录今天
   - 和它聊聊
   - 查看档案
   - 三个按钮应是首屏最明确的行动入口。
   - 按钮层级可做一主两次：记录今天为 primary，聊天和档案为 secondary。

5. 下方轻量卡片
   - 最近记录：只展示最近一条或今天是否已记录。
   - 健康提醒：只展示最需要注意的一条，不做健康分中心。
   - 纪念模式入口：仅在合适位置轻量出现，不作为首页并列主入口。

首屏原则：

- 第一屏不要堆太多模块。
- 功能入口要少而清晰。
- 宠物必须是视觉中心。
- 数据卡片只做辅助信息，不抢主角。
- 不要像普通工具型宠物 App。

## 3. 视觉风格

### Current / 正在陪伴模式

关键词：奶白、暖灰、浅棕、柔光、玻璃感、留白、温柔但不幼稚。

建议方向：

- 背景以奶白或暖灰为基底，可加入非常轻的暖色径向柔光。
- 主卡片使用半透明玻璃感，但透明度要克制，避免廉价高光。
- 宠物 Hero 区可以使用浅棕、米白或暖灰底座。
- 按钮使用柔和实色或半透明底，不用高饱和粉色大面积铺开。
- 圆角可以更大，但仍保持高级感，避免卡通玩具感。
- 阴影应轻、散、柔，不做重投影。
- 留白要足，让宠物形象有呼吸空间。

体验气质：

- 温柔、可信、日常。
- 有情感温度，但不幼稚。
- 高级但不冰冷。

### Deceased / 温柔纪念模式

关键词：月白、雾灰、低饱和蓝紫、暖烛光、安静、缓慢、克制。

建议方向：

- 布局不变，避免让用户感觉进入另一个 App。
- 背景色温降低，奶白转向月白或雾灰。
- 光晕可从暖阳感变成低饱和蓝紫与一点暖烛光。
- 按钮语义切换，例如“记录今天”变为“写一段回忆”，“和它聊聊”变为“整理想念”。
- 卡片边界更轻，文字更慢、更安静。
- 不使用黑白丧葬感，不把纪念模式做得沉重。

体验气质：

- 不假装宠物复活。
- 不制造强情绪刺激。
- 像一个安静保存回忆的地方。

## 4. 电子宠物形象 Hero

电子宠物形象是首页第一视觉主角。它应被设计成“被放在这里”的存在，而不是一个可替换头像。

位置建议：

- 位于首屏中央，承载最大视觉权重。
- Hero 高度可占首屏约 38% 到 48%，视底部导航和屏幕高度调整。
- 宠物形象可以置于柔和底座、光晕或玻璃卡片上。
- 形象周围避免堆放太多按钮、标签和数据。

没有生成形象时：

- 显示高级占位，不要空白。
- 占位可使用柔和轮廓、浅色剪影或本地 placeholder。
- 文案：“生成电子宠物形象”。
- 辅助文案：“上传一张清晰照片，让它成为首页主角。”

已生成形象时：

- 主按钮可以显示“查看电子宠物”。
- 次级入口显示“重新生成”。
- 不把重新生成做成强打扰入口。

deceased 模式：

- 入口文案可变为“查看纪念肖像 / 重新生成纪念肖像”。
- 光效更慢、更低饱和。
- 不使用夸张动态或拟生命表达。

## 5. 一张照片生成流程

第一版只要求用户上传一张宠物照片，不增加新用户启动成本。

推荐流程：

1. 用户上传一张清晰宠物照片。
2. 系统生成归爪电子宠物形象。
3. 如果用户不满意，引导换一张更清晰、角度更好的照片重新生成。

明确不做：

- 不要求用户一开始上传多张照片。
- 不做复杂拍摄教程。
- 不做强制照片质量评分。
- 不接真实 AI 图片生成 API。
- 不上传云端。

照片建议文案：

- “尽量选择光线清楚、脸部无遮挡的照片。”
- “如果效果不理想，可以换一张更清晰、角度更正的照片。”
- “先用一张就够了，之后再慢慢完善。”

## 6. 动效原则

动效目标是让首页更有生命感，但不做炫技。

建议动效：

- 页面进入：整体淡入 + 主要内容微上浮。
- 宠物形象：非常轻微的呼吸或漂浮，幅度小，周期慢。
- 按钮点击：轻微缩放回弹，反馈明确但不弹跳。
- 卡片出现：柔和过渡，延迟不要过长。
- 模式切换：色温渐变，current 到 memorial 不应瞬间硬切。
- 底部导航：当前项轻微放大或柔光增强。

实现原则：

- 优先 CSS `transition` / `animation`。
- 不使用重型动画库。
- 不做复杂 WebGL。
- 不做真 3D。
- 所有动效都要可被弱化，避免长期使用时疲劳。

## 7. 底部导航与页面过渡

底部导航可以从普通 tab bar 向更高级的玻璃感胶囊导航演进。

建议方向：

- 使用半透明玻璃底，带轻微 blur 和柔和边框。
- 当前项轻微放大，或增加低饱和柔光。
- 图标与文字保持清楚，不做过度装饰。
- 点击反馈使用轻微缩放或亮度变化。
- 页面切换不要生硬，可使用淡入或轻微位移。
- 避免每次切换都做大幅动画。

底部导航应该像“回到宠物空间的轻入口”，而不是工具栏。

## 8. 不要做什么

首页重构明确不要：

- 不要堆很多数据卡。
- 不要把健康分作为首页第一主角。
- 不要大面积艳丽粉色。
- 不要卡通游戏风。
- 不要像商城。
- 不要像普通医疗工具。
- 不要模仿竞品页面。
- 不要一开始做真 3D。
- 不要把纪念模式做成首页并列大入口。
- 不要让用户首次进入就承担多张照片上传成本。
- 不要为了高级感牺牲可读性。

## 9. 后续实施建议

下一轮代码实施建议保持小步：

- 只改 `pages/home/home.vue` 和必要样式。
- 不改 `chat` / `calendar` / `archive` 的业务逻辑。
- 不接真实图片 API。
- 先使用现有 mock 形象和占位图。
- 保留现有首页数据来源与跳转路径。
- 实现 current / memorial 两套 `themeClass` 的基础视觉差异。
- 把电子宠物形象提升为首页主视觉。
- 首屏只保留三个核心动作：记录今天 / 和它聊聊 / 查看档案。
- 保持项目可运行。

建议实施顺序：

1. 整理首页 DOM 层级，不改变业务数据。
2. 建立 Hero 区和宠物形象显示优先级。
3. 调整三个核心按钮的视觉层级。
4. 将现有记录、提醒、纪念入口降为下方轻量卡片。
5. 加入 current / memorial 基础主题变量或 class。
6. 加入克制动效。
7. 真机或浏览器检查不同屏幕高度下首屏是否仍以宠物为中心。
