# 宠物全局色调与返回首页恢复

## 本轮范围

修复返回首页后猫图进入等待状态，并新增可切换的全局同色方案。保留上一版局部舞台，不修改生图 Provider、Base Prompt、真实配置或 uni_modules；不提交 Git。

## 根因与修复

1. 临时 URL 缓存的五分钟刷新周期被当作展示有效期。到刷新边界时，仍有效的图片地址会从选择器消失。现在区分“应该刷新”与“已经失效”，后台续期失败不会抹掉仍有效的主图；真正过期或已报错的地址仍会拒绝。
2. URL 恢复结果与首页计算属性有不同更新路径，部分恢复依赖缓存通知。首页现在也订阅自身 hydration 结果，错误恢复后更新展示版本；空结果执行最多三次、带宠物/任务所有权检查的 URL 恢复。不会重新生成图片。
3. 展示组件在同一资源 URL 切换时丢弃已解码图片，且未加载时仍绘制右侧背景延展。现在仅同一宠物、同一资源保留上一张已解码图；换宠物或换主图立即清空。返回页面重新测量，采样异常保留上次有效色板。

## 全局同色

- 默认启用；“设置 → 界面与显示 → 宠物色调”可选择“全局同色 / 局部舞台”。两者都保留。
- 色板归属为 petId + 已确认 master fileId，不以临时 URL 为身份；持久化最多 12 组色板，迟到的旧宠物采样不能改写当前主题。
- 仅接受已通过舞台背景判断的浅中性色：RGB 通道合法、最小通道 > 115、最大通道差 < 48。深色、高饱和或不合格背景采用安静的默认中性色。
- 页面底色、浅色卡片、深色按钮、文字、分隔线和原生底栏由同一色板派生。主图不加模糊、不改变毛发颜色，也不把照片铺成全屏背景。
- 16 个 manifest 中的自有页面均接入主题根节点；系统权限窗口与 uni_modules 的第三方页面不强行染色。

## 审美判断与边界

保留方案使用同源暖灰的明暗层级组织全页：宠物背景与页面不再冷暖冲突，浅卡片承载文字，深按钮建立操作重点。没有扩大羽化区域、模糊主体、重阴影或高饱和全屏染色。

这是全 App 色彩系统升级，并非重画所有页面结构。旧页面各自的卡片密度和排版仍在；所有页面都接入了主题，但逐页人工观感验收仅覆盖上述四页。极端背景不直接取色，是为避免换一只宠物就产生刺眼或低对比界面。
