# 开发多宠与纪念头像跳转测试

## 变更边界

- 多宠豁免只由根目录 `.env.development` 和 `common/dev-flags.js` 的开发环境开关控制。
- 免费用户在开发环境最多创建 3 只测试宠物。
- 生产环境继续执行原免费 1 只、Plus 会员多宠规则。
- 头像跳转只对 `deceased` 纪念聊天生效。
- 本轮不创建人格训练页面；未来 Phase 3 入口挂载在宠物档案页。

## 静态判断矩阵

| 环境 / 权益 | 当前数量 | 预期 |
| --- | ---: | --- |
| 开发 / 免费 | 1 | 允许创建第 2 只 |
| 开发 / 免费 | 2 | 允许创建第 3 只 |
| 开发 / 免费 | 3 | 阻止，并提示开发测试上限 |
| 生产 / 免费 | 0 | 允许创建第 1 只 |
| 生产 / 免费 | 1 | 阻止，并保留原会员提示 |
| 生产 / Plus | 任意 | 保留原多宠权益 |

## 真机测试步骤

### 1. 开发环境创建多宠

1. 使用普通未开会员账号，确保已有 1 只宠物。
2. 在“我的”页点击“添加”，确认进入 welcome 创建页。
3. 完成第 2 只和第 3 只宠物创建。
4. 再次点击“添加”，确认出现“当前开发测试最多创建 3 只宠物。”。
5. 检查控制台出现开发变量诊断和 `[PET CREATE ACCESS]` 权限结果。

### 开发变量生效

1. 修改 `.env.development` 后停止当前运行。
2. 在 HBuilderX 中重新编译并安装运行包，热更新不足以保证编译期变量刷新。
3. 控制台应看到：
   - `[DEV FLAGS] mode=development`
   - `[DEV FLAGS] allowMultiPetTesting=true`
   - `[DEV FLAGS] source=VITE_ALLOW_MULTI_PET_TESTING`
   - `[PET CREATE ACCESS]` 及本次 `petCount / allowed / reason`
4. 若日志完全不存在，优先清除旧运行基座缓存或卸载旧测试包后重新安装。

### 2. 生产规则

1. 使用生产构建检查 `allowMultiPetTesting` 为 `false`。
2. 普通用户已有 1 只宠物时点击“添加”，确认仍显示原会员提示。
3. 确认没有开发豁免日志，会员状态与支付逻辑均未变化。

### 3. 宠物 A / B 隔离

1. 创建宠物 A，并设置为 `deceased`。
2. 创建宠物 B，并保持为 `current`。
3. 分别进入聊天页，确认历史记录按宠物与阶段隔离。

### 4. 纪念聊天头像跳转

1. 切换到宠物 A 的纪念聊天。
2. 点击顶部宠物头像，确认进入宠物 A 档案。
3. 返回聊天，确认仍为宠物 A、`deceased` 模式，原聊天历史保持。
4. 点击任意 AI 消息左侧头像，重复确认目标档案与返回状态。
5. 在“正在输入”出现时点击头像，确认仍只跳转一次。

### 5. 切换与旧消息保护

1. 从宠物 A 切换到宠物 B，再切回宠物 A。
2. 确认头像与目标 `petId` 已更新。
3. 快速连续点击头像，确认不会重复打开档案页。
4. 若消息中的 `petId` 与当前 activePet 不一致，确认不会发生跳转。

### 6. current 回归

1. 进入宠物 B 的 current 聊天。
2. 确认顶部头像、AI“护”头像行为保持不变。
3. 连续追问照护问题，确认问诊上下文和聊天隔离不受影响。
