## 4. 首选方案与控制台步骤

首选**阿里云OSS专用私有Bucket + 后端签发单对象POST直传/GET授权**。Bucket从首次写入即私有，开启阻止公共访问；手机拿受限表单直传，不把大图强制经云函数中转。后端决定用途、路径、大小和时限，Secret只留服务端。[官方PostObject](https://help.aliyun.com/zh/oss/developer-reference/postobject)支持上传时private及防覆盖；[阻止公共访问](https://help.aliyun.com/zh/oss/user-guide/block-public-access/)阻止公共授权。这是基于支持能力的推荐，尚非本项目已验证配置。

你只需在**阿里云控制台**完成以下准备；没有现成资源时，由你决定接受协议和新建资源，本轮没有代办或购买：

1. OSS → Bucket列表：选一个专用Bucket；没有则由你创建，记录名称和地域。权限设私有，开启该Bucket的阻止公共访问，检查没有公共Bucket Policy；先不接CDN。选**从未开启版本控制**的Bucket，Enabled/Suspended都会使防覆盖参数失效，不能靠“暂停”解决。
2. RAM → 用户/权限：准备仅服务端使用的专用凭据，按该Bucket的`pety-private-v4/*`范围给GetObject、PutObject，及私有ACL写入所需权限；目标核验另给只读ACL/Policy/公共访问阻止/版本状态权限。不用主账号或模型密钥，不授予客户端长期Secret，不授予删除/宽目录权限。准确RAM策略与真实直传响应下一轮核对。
3. OSS → 权限控制 → 跨域设置：为实际H5测试/正式Origin配置POST、GET、HEAD及需要的Header，暴露ETag/x-oss-request-id；不把CORS当鉴权。App直传与uni.uploadFile表单兼容仍需真机验收。[官方CORS说明](https://help.aliyun.com/zh/oss/user-guide/configure-cross-origin-resource-sharing)
4. 通过本地服务端配置填写`provider`、`bucket`、`region`、`endpoint`、`accessKeyId`、`accessKeySecret`；endpoint使用`https://<bucket>.oss-<region>.aliyuncs.com`。从示例保留prefix及TTL，**enabled先保持false**。不要把Secret发到聊天；下一轮告知配置位置即可。云端配置同步留到接线完成后的单独部署步骤，不必现在改uniCloud规则。

## 5. 新文件、旧文件与旧入口

- **新文件**：既有认证及回执发票据→手机受限直传→后端检查真实图片、完成原回执→业务引用。生成图继续原质量检查，随后由服务端私有写入；模型保留按归属与哈希读原字节的方式，必要时才给任务短期URL，不公开整个图库。
- **旧照片/生成图**：本轮不读图、不迁移。后续先备份准确引用与权限、确定归属、生成逐项dry-run清单；缺可信归属的旧对象不自动认领。拷贝原字节到私有对象，核对SHA/大小/尺寸，再给已有记录增加存储定位；保留旧稳定ID、派生关系及缓存键，先保留旧源文件作恢复点，不批量改宠物记录。
- **旧公开URL/CDN**：新Bucket不会撤销它们。需逐项确认旧源站改权/删除的能力、旧下载授权最大有效期，以及CDN刷新/预热副本撤销和最长TTL。公开链接可能没有到期时间，不能只等签名过期；源站私有也不等于CDN副本立即消失。已被下载的副本无法远程收回。
- **旧平台入口**：尚无官方确认可关闭当前支付宝空间的客户端上传授权/临时下载签名入口。移除前端调用、关闭自写签名API或开启安全网络不能证明平台入口关闭。需向DCloud支持准确确认：①能否按空间/APPID禁用客户端getUploadFileOptions/uploadFile/getTempFileURL并保留服务端及账号资料查询？②能否要求当前uni-id身份、校验对象归属和准确路径，并覆盖官方SDK/REST/云对象包装入口？③旧目录能否无损改私有、如何撤销既发授权、CDN如何批量刷新及最长失效时间？④若不能，是否存在官方支持的仅服务端空间/凭据隔离办法，以及旧空间上传入口与费用风险如何最终关闭？本轮没有发工单或模拟这些入口。

**恢复准备**：迁移前保存逐项映射、元数据与私下备份；灰度切换后保留原字节及原缓存。失败仅回滚新映射/停用新写入，保留已成功私有对象和业务回执，不删数据、不降低鉴权，不把重新公开旧图当恢复方案。无法安全远程读取时保留本地缓存并显示待修复。旧入口未解决仍是独立缺口。

## 6. 配置到位后的最小真实验收

先补齐SDK、权限检查、现有回执/生成持久化/URL解析接线并备份待部署版本。另行授权后，仅用一张小型合成图和正常隔离A/B身份：A手机直传→complete→读取；无签名源站拒绝；无身份及B不能取得A的新授权或修改/删除对象；篡改key/ACL/MIME/大小、过期票据和同key重传被拒绝；签名到期后原缓存仍可读、缓存未命中经归属接口续期。生成图持久化可用合成Provider字节验证，不调用模型。

签名是有效期内的持有者授权，泄露的现成签名在到期前不自动绑定A身份。模型URL实际可读性留给随后另行授权的最小模型测试；本轮及上述验收都不发短信、不付款。最后单独验证旧源站/CDN撤销和旧平台入口限制，不能仅验新Bucket就宣称旧风险消失。
