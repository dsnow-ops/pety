## 0. 本轮纠偏：不再把“参考”理解为自由发挥

用户已经明确认可随包 `reference/USER_APPROVED_SCREENSHOT.png` 的视觉。目标是先达到这个方向，而不是再交一个“自己的浅色理解”。

核对发现：此前 `GUIZHUA_HOME_AND_FREE_SEAL_REFERENCE.html` 默认实际是浅色：`--bg:#f5f2eb`，`--surface:rgba(255,255,250,.76)`，`--ink:#29312c`；而用户认可的截图是深暖色。旧交付 `docs/UI_SYSTEM_V2.md` 也采用了浅色值。这是可确认的规格不一致；为什么截图和默认 HTML 颜色不同尚无证据，不能声称已证明是某个插件或系统功能造成。

因此本轮以用户认可截图为最高视觉方向，以 `reference/APPROVED_EXPLICIT_REFERENCE.html` 为显式主题、布局与操作的可运行母版。它保留旧 HTML 的布局与印记演示，只把深暖色写为实际 CSS，并提高部分小字可读性；独立演示中的 Hero 占位从470缩到450逻辑px，为固定底栏保留周历空间，不裁切宠物。正常干净浏览器环境可显示，无需强制深色或滤镜。

这里的深暖色是 UI 表面，不是给照片加滤镜。**宠物高清资产、照片、纸面 PNG 不许整体变暗或反色。** 纸仍然为米白，界面承托为深暖色。不要恢复默认浅奶油面板和浅底 tabBar。

## 4. 规整是“同职责相同”，不是“所有东西相同”

全部尺寸为逻辑 CSS px。基准宽390，同时检查360、375、412；不得把1312物理截图像素当设计尺寸。宽度使用容器和 flex/grid，控件高度/字号用一致策略。若既有工程必须rpx，换算并测量最终逻辑尺寸，不能直接把48px写成48rpx。

|角色|普通字号模式几何|应用位置|
|---|---|---|
|主要/次要动作|48高，14圆角，15字/22行高，20图标，图标间距8，内边14|首页记录/问诊、保存日常记录、制卡存册/导出|
|图标触控|44×44 hit area，图标20–22|返回、更多、上一周下一周|

|健康事件|12项三列四行等宽；hit44高，face38高/10圆角，文字14/20，水平间距8|既有十二个分类；不要再做竖椭圆|
|五状态|同一行五等分，hit44高，face38高，字13/20；大字时重排|轻松/平稳/疲惫/不安/不适|

`code/visual-lock.roles.css` 是能在参考页验证的角色样式，不是未经审查直接覆盖全仓的补丁。优先合并到现有组件，不新建第二套同用途控件；处理既有props、class透传、scoped边界、按钮事件与disabled等状态。

## 5. 用户每个圈，必须有对应修复

### A. 首页“记录今天 / AI问诊”

同一行两个48高按钮；使用母版的深面板、低饱和主按钮和深色次按钮。圆角、文字基线和图标中心一致。主次不能靠大白矩形/不同高度区分。标题21，而不是越改越大。

### B. 健康十二个事件

三列四行，按当前实际顺序和键保留全部12项。文字水平垂直居中；从未选、已选、点击、禁用到保存重开，几何尺寸保持不变。选中有填色及可感知状态，不用颜色掩盖文字。仅点标签仍不是填写健康结果，原语义不变。

检查并修正原生按钮默认行高/内边距/伪元素、旧样式选择器、flex伸展；提交原因与具体规则，不只是末尾再叠 `!important`。

### C. “保存日常记录”

和首页主按钮相同高度、圆角、字号；只有宽度为整行。正文与按钮之间保留16–20间距。保存后不强制制卡；未填写保持未知。

### D. “健康与观察 / 日常与照片”

这是一个分段选择器，不是两个并排的大保存按钮。外框44、激活面36，两个单元等宽、文字中心相同；原日常/健康共用日期与一次保存，不回到两套存储。

### E. 周历选中日期

保留当前7列、农历与日期逻辑，移除来自容器拉伸/按钮默认样式的超高药丸。普通模式74高、16圆角；“今”在单元内部保留位置，不顶出边界。系统字体差异允许，但宽高/间距不得明显偏离母版。

### F. 首页“陪伴册”

不是一个标题+解释+一整条巨型白按钮的空栏目。严格区分两种状态：
- 有作品：用当前宠物已有真实作品缩略图呈现1–2件，标题行一个“查看全部”；不要另外重复“陪伴册/翻开陪伴册”等三个同义入口。
- 无作品：一块深暖色、紧凑的空状态，最多一行说明和一个入口。不能伪造已有作品；需要样例时明确“版式示例”，不得写进业务数据/计奖。

档案与专属形象归入一组轻设置行，可保留原入口，无需在首页底部突然散落几段大小各异的文字。提案仍低权重、可收起，不增加任务感。

### G. 我的页“账号与安全”

把它作为同组设置行/尾部轻动作，而不是与“保存记录”同权的大绿色胶囊。账号状态与本机/云同步状态必须准确；不显示UID作为主要视觉，也不能删除必要诊断入口。当前“回忆纪念册：尚未接入”等旧文案应按实际能力审查，不能一边已有制卡一边笼统写未接入；区分本地记录/导出已可用与云同步/真实润色未联调。不要把能力可达修复当成本轮新增云功能。

截图中“3/1”宠物数量需要查实际规则和历史兼容，不能为了美观删除宠物、放开额度或隐藏无法继续添加的真实原因；本轮只调整表达，遇规则疑问留明确记录。

每张：用户认可母版/本轮开始时实际页/修改后实际页。比较的是应用内容区，不包括演示网页标题、手机外框和假状态栏。首页按同宠物同素材同逻辑宽度对齐；不知道确切图像区域就说明，不冒称像素级同材质。

### 尺寸门槛（标准字号，同视口）

- 按钮、segment、choice、周历单元的高度与合同差不超过2逻辑px。

- 360/375/390/412普通字号无横向溢出；系统大字体另验，允许按规则重排。
- 正文、按钮、状态对比度可读；母版中低对比小字应修正，不机械照抄可读性缺陷。

比较时仅允许为统一逻辑宽度做等比例归一化，不能单独拉长某区域/裁掉失败控件/调色处理真实截图。保留原始截图。不要拿不同滚动状态声称前后精确对照。

## 8. 防止“网页好看，App变形”的执行要求

- 实际目标是Vue3 App-vue。不要拿uni-app x/nvue限制解释或强行迁移。
- 普通布局优先 flex；参考中的grid可在实际目标端验证或等价转为flex，最终几何必须一致。
- CSS px是逻辑单位；在`.gz-*`或当前组件内部限定height/line-height/padding/box-sizing，避免影响开放平台授权button。
- 不用原生type=primary假设多端同色，明确使用项目样式；loading/disabled状态不跳尺寸。
- 顶部safe area按已验证机制，只算一次；状态栏固定层与滚动内容分离。截图中内容穿到状态栏下方时，看是否合规沉浸遮罩，不擅自把所有页面整体下移一个写死高度。
- 底部导航需和深暖色背景协调且有统一线性图标。优先更新当前已有tabBar配置/组件；没有custom tabBar时不要为半透明强行全局改路由。支持不到模糊时使用同色不透明背景。导航路由、选中态、返回和安全区回归。
- 页面和sheet会被不同容器包住，确认CSS变量能够到达实际根。对不继承的边界传主题类/变量，不靠父级恰好染到所有东西。
- 不依赖系统自动深色。普通和暗色系统设置下都核对本轮显式品牌皮肤；对浏览器扩展影响只说明验证环境，不承诺任意扩展无法重写页面。
